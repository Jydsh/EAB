# EAB P0：项目命令 OS 沙箱 v1（AGT-05b）

日期：2026-11-24  
范围：`project.exec` / `project.job` 的 strict 沙箱、网络拒绝、命令白名单  
版本：`2026.11.23.04`（未改版本号，未 commit，未 push）

## 1. 这一版解决什么

之前 `project.exec` 只有命令黑名单和路径锁，明确标注 `enforcement: none`，不是安全边界。任何人拿到执行权限后，只要命令不在黑名单里，就能读写工作区、访问网络。

这一版把执行模式拆成三档，并把真实执行边界写进返回：

| 模式 | 启动方式 | 文件隔离 | 网络 | 白名单 |
| --- | --- | --- | --- | --- |
| `off` | 不启用 | — | — | — |
| `local` | `EAB_PROJECT_EXEC=1` | 无，仅工作区路径锁 + 黑名单 | 不限制 | 可选 |
| `strict` | `EAB_PROJECT_EXEC=strict` | Docker 或 bwrap OS 隔离 | 默认拒绝 | 必须配置 |

strict 模式没有可用后端时**直接拒绝执行**，不会悄悄回落到 local。

## 2. 后端

### Docker

`EAB_PROJECT_SANDBOX_BACKEND=docker`，启动参数包含：

- `--network none`：容器内断网。
- `--read-only` + `--tmpfs /tmp`：根文件系统只读，临时目录受限。
- `--cap-drop ALL` + `--security-opt no-new-privileges`：去掉能力，禁止提权。
- `--pids-limit` / `--memory` / `--cpus`：限制进程数、内存和 CPU。
- `-v <工作区>:/workspace:rw`：只挂载当前用户工作区。
- `-w /workspace[/子目录]`：工作目录不能跳出工作区。

镜像默认 `node:22-bookworm-slim`，可用 `EAB_PROJECT_DOCKER_IMAGE` 覆盖。Docker 里跑的是 Linux bash，不是 Windows PowerShell；项目命令需要兼容 Linux 工具链。

### bubblewrap

`EAB_PROJECT_SANDBOX_BACKEND=bwrap`，启动参数包含：

- `--unshare-net --unshare-pid --unshare-ipc --unshare-uts`：网络和进程命名空间隔离。
- `--ro-bind /usr /bin /lib ...`：系统目录只读。
- `--bind <工作区> <工作区>`：只写当前工作区。
- `--tmpfs /tmp`、`--clearenv`：临时目录和环境变量清空。
- `--chdir <工作目录>`：不能跳出工作区。

### 自动探测

`EAB_PROJECT_SANDBOX_BACKEND=auto`（默认）：

- Linux：先找 `bwrap`，没有再找 `docker`。
- Windows / macOS：找 `docker`。
- 显式 `none`：关闭后端，strict 模式会拒绝执行。

Windows 原生没有可用的文件/网络隔离后端，所以本机默认只能是 `local`。安装 Docker Desktop 并让 daemon 运行后，才能设置 `EAB_PROJECT_SANDBOX_BACKEND=docker` 使用 strict。

## 3. 命令白名单

`EAB_PROJECT_COMMAND_ALLOWLIST` 每行一条正则，命令必须至少命中一条；`#` 开头为注释。

示例：

```text
# 只允许测试、类型检查和构建
^pnpm\s+(test|typecheck|build)$
^npm\s+run\s+(test|build)$
^git\s+status$
```

规则：

- 黑名单先执行，命中直接拒绝。
- 白名单非空时，未命中直接拒绝。
- strict 模式白名单为空时，拒绝所有命令；不能靠“沙箱里就随便跑”绕过。
- 正则非法时直接报 `EAB_VALIDATION`，不会静默忽略。

## 4. 返回字段与控制台

`project.exec` 和 `project.job` 现在返回：

- `enforcement`：`none` / `docker` / `bwrap`，表示实际执行边界。
- `sandboxMode`：`off` / `local` / `strict`。
- `network`：`unrestricted` / `denied`。

控制台「知识与模型 → 工具 → 调用规则」新增「项目命令」一行，读取 `/api/tools` 里的 `projectExec` 状态：

- `off`：未启用。
- `local`：本地执行，只有路径锁和黑名单，没有 OS 隔离。
- `strict + docker/bwrap`：显示后端、网络拒绝和白名单条数。
- `strict` 无后端、白名单为空或正则非法：明确标为未就绪，并说明会拒绝执行。

模型和审计都能看到“这次到底有没有隔离”，管理员也能在控制台确认当前配置，不再靠文档猜。

## 5. 本机验证边界

本机当前没有 Docker、bwrap、WSL 发行版，因此：

- 已验证 strict 无后端时 fail-closed，不会回落 local。
- 已验证 Docker / bwrap 的参数构造包含断网、只读、权限降级和工作区挂载。
- **没有做真实容器内执行验证**。要完成真机验收，需要安装 Docker Desktop 或 Linux 上的 bubblewrap，再跑一条只读命令和一条网络命令确认被拒。

这是本轮必须说清楚的缺口：代码路径和策略已落地，但没有可用后端，不能声称“真实容器已跑通”。
