# EAB P1 多模态内容工具 v1（AGT-19）

日期：2026-11-24
范围：外部图片生成适配 v1。只做「文字 → 图片 → 存个人云空间」，不接视频生成，不把图片生成混入核心问答链路。

## 1. 解决了什么

审计项 AGT-19 的原始要求是：图片 / 视频生成或外部工具适配，不混入核心问答链路。此前 EAB 已有 `asr`、`tts`、`video` 端点，但没有图片生成端点，也没有任何 `/images/generations` 调用。

v1 选择最小闭环：

- 新增模型端点类型 `image` 和用途 `image.default`（图片生成）。
- 新增 OpenAI 兼容图片生成调用，读取 `data[0].b64_json` 或 `data[0].url`，校验真实图片头。
- 新增独立接口 `POST /api/content/images`，生成结果直接落当前员工个人云空间。
- 新增内置工具 `content.generate_image`，只在明确画图意图时由能力路由下发。
- 控制台模型表单增加「图片生成模型」类型与端点；用途路由页自动出现「图片生成」。

## 2. 数据与配置

不需要新表。图片模型仍走现有 `model_providers` + `models` + `model_routes`：

- `models.endpoint_kind = 'image'`
- 用途路由 `model_routes.purpose = 'image.default'`
- 服务端调用 `POST {base_url}/images/generations`

显式绑定优先；未绑定时，按 `endpoint_kind === 'image'` 自动挑选。模型名含 `gpt-image`、`dall-e`、`flux`、`stable-diffusion`、`sdxl`、`imagen`、`seedream`、`kolors`、`image-gen` 等特征时，导入模型会自动推断为图片生成端点。

管理员配置步骤：

1. 控制台「模型」页新建供应商，填 OpenAI 兼容 Base URL（例如 `https://api.openai.com/v1`）和 Key。
2. 新建模型，类型选「图片生成模型」，端点选「图片生成 / images generations」，模型标识填供应商侧真实模型名。
3. 在「模型用途 / 路由」把「图片生成」绑定到该模型；不绑定则自动按端点挑第一个可用的。
4. 员工侧不需要额外配置。

## 3. 接口

`POST /api/content/images`

请求：

```json
{ "prompt": "画一张公司年会海报，蓝金配色", "size": "1024x1536" }
```

响应：

```json
{
  "ok": true,
  "data": {
    "file": { "id": "...", "name": "生成图片-20261124-153000-xxxxxx.png", "relPath": "...", "size": 12345, "mime": "image/png", "root": "user" },
    "downloadUrl": "/api/workspace/files/<id>/download",
    "modelKey": "gpt-image-1",
    "revisedPrompt": "..."
  }
}
```

约束：

- 需要 `workspace:write` 权限，账号必须是启用状态。
- `prompt` 必填，最长 2000 字。
- `size` 可选，只接受 `宽x高`（如 `1024x1024`）。
- 接口挂在员工端口，不挂在管理端口；没有登录时返回 401。
- 不再额外调用聊天模型，不写消息历史，不占对话上下文。

## 4. 图片调用细节

`callImageGeneration` 在 `llm.ts` 中实现，复用现有供应商、Base URL 与密钥解析：

- 请求体：`{ model, prompt, n: 1, size? }`。
- 支持两种返回：base64 或远程 URL；URL 会再下载一次，超时 60 秒。
- 只接受 PNG / JPEG / WEBP / GIF 魔数，防止供应商把 HTML 错误页或 JSON 当图片。
- 单张上限 24MB；提示词与尺寸做前置校验。
- 上游非 2xx 时把状态码和响应体摘要回给用户，并提示核对 `/images/generations` 与模型名。
- `demo`、`anthropic`、`gemini` 等没有标准图片端点的供应商会直接给出明确提示，不会偷偷退回聊天模型。

## 5. 工具与路由

新增工具 `content.generate_image`：

- 作用域 `workspace:write`，并发属性 `write`。
- 入参 `prompt`（必填）、`size`（可选）。
- 返回 `fileId`、`name`、`relPath`、`size`、`mime`、`downloadUrl`、`modelKey`。
- 执行结果走同一条 `generateImageToWorkspace`，与 HTTP 接口共用配额、落盘、元数据与审计。

能力路由新增 `content` 组，只在明确画图意图时下发：

- 命中：`帮我画一张海报`、`生成一张重庆夜景插画`、`做个头像`、`draw me a ...`。
- 不命中：`把图片发给我`、`检查记录有多少条`、普通问答与文档写作。

未命中时模型仍可通过 `tool_search` 搜索并加载，不需要把图片工具常驻在核心工具组。

## 7. 边界

- 只支持 OpenAI 兼容 `/images/generations`。Gemini 的 `generateContent` 图片模式、Anthropic 图像接口、ComfyUI 工作流、视频生成都没有接入。
- 没有接真实公网图片供应商，未做真实出图验收；当前真实证据是本地假供应商 + `app.inject`，以及控制台 API 与页面资源检查。
- 控制台新增图片类型下拉只做了资源返回检查，未做真实浏览器点击验收。
- 图片不写聊天消息，因此员工在对话里让 Agent 画图时，结果以云空间文件形式返回；若要直接在对话气泡里展示图片，需要另做消息附件/富媒体卡片，不在 v1 范围。
- 生成图片会占用个人云空间配额，受现有单文件上限与公司/个人配额约束。
- 没有图片编辑、参考图、多图批量、透明度控制、尺寸白名单；这些留给后续。
- 未改版本号，仍为 `2026.11.23.04`；改动未 commit、未 push。
