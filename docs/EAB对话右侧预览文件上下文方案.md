# 右侧预览文件上下文方案

> 问题：右侧预览开着文件时，Agent 并不知道用户在看哪个文件，于是反问「你要改哪个文件」。
> 判断：这不是模型能力问题，是**上下文没给**。只要把「当前预览文件」随本轮消息送上去，并在提示词里明确「这个文件」指谁，问题就消失。

## 一、可选方案

| | A 随消息上报（已落地） | B 仅提示词注入 | C 后端记「最近打开」 | D 会话级 active_file |
|---|---|---|---|---|
| 做法 | 前端每次发消息带 `activeFile{id,name,relPath}`，服务端写进本轮系统提示 | 同 A 但只有一个文件名字符串，不含 fileId | 新增「打开文件」事件，后端按用户记最近文件 | `chat_sessions` 加 `active_file_id`，随会话持久化 |
| 模型能否直接动手 | 能（拿到 fileId 可直接 office_find / office_replace） | 不能，需要先 tool_search 或反问 | 能，但不准 | 能 |
| 跨刷新/重连 | 刷新后右侧面板关闭，不传即不生效（符合直觉） | 同 A | 会残留上次文件，容易指错 | 保留，但多端会互相覆盖 |
| 多设备/多会话冲突 | 无（只属于这一次请求） | 无 | 有 | 有 |
| 改动量 | 前端 1 处 + 服务端 1 处校验 + 提示词 1 段 | 更小 | 中（含新接口与存储） | 中（含迁移与清理） |
| 风险 | 低（默认不传即原行为） | 低 | 中（错误上下文比没有更糟） | 中（状态脏了会一直错） |

**结论：A +（可选）D**。C 明确不采用——「猜当前文件」比「没有上下文」更容易误导。

## 二、已落地的部分（A）

### 前端
- `chat.js` 新增 `activePreviewFilePayload()`：只有右侧面板真的打开、且 `state.filePreview` 有值时才返回 `{id, name, relPath}`；
- 两条发消息路径都带上：正常发送（`streamChat` 主流程）与引导式澄清的续跑请求。
- 面板关闭 / 没有文件时返回 `undefined`，服务端行为与升级前完全一致。

### 服务端
- `POST /api/chat/messages` 新增 `activeFile?: {id, name, relPath}`，只做长度截断（id ≤ 120、name ≤ 200、relPath ≤ 500），不落库、不进历史；
- 两个字段都齐才生效；`spaceKind = none` 时忽略（那时没有任何文件工具，说了也无法动作）；
- `buildSystemPrompt` 新增 `activeFile` 入参，插在文件空间规则之后：

> 用户此刻在右侧预览《X》（fileId=…，云空间路径 …）。用户说「这个文件 / 这份文档 / 这张表 / 它 / 这段」时默认指这个文件：需要读取或修改就直接用它上面给的 fileId，不要反问「是哪个文件」。只有用户在消息里明确写了别的文件名、或本条带了附件时，才以用户说的为准。

### 测试
`chat-system-prompt-space.test.ts` 增加 2 例（带预览文件时出现该段并含 fileId、路径、「不要反问」；没有时不出现），4 例全过。

## 三、下一步（按需再做，不急）

1. ~~**工具参数兜底**~~ **已落地**：`ToolExecutionContext.activeFile` + `withActiveFileDefaults(toolId, args, activeFile)`——`office_*` 在 fileId 与 path 都缺时自动补当前预览文件的 fileId，`workspace.read` 在缺 path 时补相对路径；模型自己给了值就一律不覆盖，其它工具不动。测试 `tool-active-file.test.ts` 4 例。提示词里同步补一句「调用 office_* 时也可以省略 fileId」。
2. **跨轮次记忆（方案 D）**：只有在用户反馈「关掉预览后再说『刚才那个文件』模型就不认」时再加，配套文件删除时清理。
3. **草稿态提示**：模型正在生成、还没落盘的文件草稿（`fileStreamDraft`）也可作为 `activeFile{draft:true}` 上报，避免模型把草稿当已保存文件去读。

## 四、边界与不做什么

- 不把预览**内容**塞进提示（内容可能很大、且随时变化）；只给身份，正文仍由工具按需读取。
- 不把 `activeFile` 写进 `chat_messages.meta`，避免历史消息被污染；要审计时看请求日志即可。
- 不做「按最近打开猜」。
