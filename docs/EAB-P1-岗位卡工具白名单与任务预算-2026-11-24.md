# EAB P1 · 岗位卡工具硬 allowlist 与任务预算硬停（AGT-10）

> 日期：2026-11-24
> 对应审计项：`docs/EAB-Agent框架对照审计与能力建设需求-2026-11-23.md` 的 AGT-10
> 目标：岗位卡的工具清单变成运行时硬 allowlist；任务 token/时长超限直接失败并留告警，不再伪装成“部分成功”。

## 一、升级前的缺口

- `AgentCard.tools` 只进入主 Agent 的编队摘要，运行时子 Agent 仍按能力路由拿到工具；卡外工具（包括 `tool_search` 重新加载）实际上可见。
- 岗位卡已有 `maxRounds / timeoutMs`，但没有 `maxTokens`；工程任务又把轮次上限放宽到 2000，等于没有岗位级执行上限。
- `TaskBudget` 字段和 `markTaskUsage` 已存在，但同步/后台派活创建任务时都不写预算，`deadline_at` 也是空。
- `runAgentTurn` 的 `budget` 只作为展示值；执行控制器只认轮次、总时长、工具次数、思考字数，没有 token 停止原因。
- 子 Agent 碰到预算停止时仍按正常返回处理，任务行可能被标记 `succeeded`。

## 二、岗位卡工具硬 allowlist

### 唯一来源

岗位卡 `tools` 是工具 id 清单，也是运行时唯一来源。新增 `resolveAgentTaskPolicy(cards, role, requestedBudget)` 统一把岗位解析成：

- `toolIds`：去重后的工具 id 白名单；
- `budget`：岗位卡与任务显式预算合并后的硬上限；
- `deadlineAt`：有 `maxDurationMs` 时的绝对截止时间。

岗位卡未登记、已停用或 `health=offline` 时直接拒绝派活；工具清单为空也不允许派活，避免出现“什么都做不了”的空岗位。

### 内置岗位工具集

| 岗位 | 工具（id） |
| --- | --- |
| researcher | `tool.search`、`kb.search`、`web.search`、`web.fetch`、`workspace.list/read/search`、`agent.ask_parent`、`agent.publish_artifact` |
| builder | `workspace.list/read/search/write/edit`、`project.exec/job`、`office.read_outline`、`agent.ask_parent`、`agent.publish_artifact` |
| critic | `workspace.list/read/search`、`project.exec/job`、`office.read_outline`、`review.verdict` |
| producer | `office.read_outline/find/replace/rewrite`、`workspace.list/read/search/write`、`agent.ask_parent`、`agent.publish_artifact` |
| worker | `tool.search`、`workspace.list/read/search/write/edit`、`project.exec/job`、`office.read_outline/find/replace/rewrite`、`agent.ask_parent`、`agent.publish_artifact` |

说明：

- `agent.ask_parent` / `agent.publish_artifact` 必须写进岗位卡，不在运行时偷偷放行；这样“协议工具”也受同一张卡约束。
- `review.verdict` 只给 critic，且独立验收员本身也只拿到 critic 卡的工具集。
- worker 扩成通用执行集：默认 `agent.spawn` 省略 role 时会落到 worker，如果只留只读工具，原有“默认派活写文件”会全部失败。

### 两道收口

1. `toolSpecsForAgent` 接收 `toolIdAllowlist`，把卡内工具直接加入本轮工具目录，不再要求任务文本先命中 workspace/project/office 路由关键词；空间和权限过滤仍然生效。
2. `runAgentTurn` 在 `tool_search` 动态加载之前按白名单过滤 `allTools / tools`，因此卡外工具既不在首轮工具表里，也无法通过搜索加载。

## 三、任务预算硬停

### 岗位硬上限

| 岗位 | maxRounds | timeoutMs | maxTokens |
| --- | --- | --- | --- |
| researcher | 40 | 300 秒 | 120,000 |
| builder | 120 | 1,800 秒 | 400,000 |
| critic | 30 | 300 秒 | 150,000 |
| producer | 60 | 1,200 秒 | 200,000 |
| worker | 80 | 1,200 秒 | 200,000 |

任务可在 `agent.spawn` 的 tasks 项里传 `budget: { maxTokens, maxDurationMs, maxRounds }`，但只能收紧岗位卡，不能把上限调大。`maxCostMicros` 只落库，当前没有模型单价，不做成本硬停。

### 落地方式

- `TaskBudget` 随任务创建写入 `agent_tasks.budget_json`，同时写 `deadline_at`。
- 子 Agent 启动时用 `AbortSignal.any([父信号, 任务时钟])`；时长到点中止在途模型调用，且**不重试**，避免超时后换模型继续烧预算。
- 执行控制器新增 `tokens` 停止原因和 `afterTokenUsage(totalTokens)`；每轮累计 `promptTokens + completionTokens`，到线立即停止工具循环。
- `AgentTurnResult` 新增 `budgetStop`。派活层看到 `budgetStop` 时：
  - 任务行标 `failed`，错误写明“任务预算硬停：…（已用 x tokens / y 轮）”；
  - 写 `agent_events` 告警，`kind=budget_exhausted`，带 `reason / rounds / tokens / maxTokens / maxDurationMs / maxRounds`；
  - 不进入独立验收员，也不把半截结果当完成汇总。
- 模型不响应中止信号时，结果返回后若任务时钟已到点，同样按失败收尾。
- 后台全局兜底超时不再固定 20 分钟：至少晚于最长岗位卡时长 5 秒，让岗位卡自己先按时钟收尾。

## 四、数据与接口

本次没有新增迁移。复用既有：

- `agent_tasks.budget_json` / `deadline_at` / `used_tokens` / `used_cost_micros`；
- `agent_events.kind` 新增取值 `budget_exhausted`，不需要改表结构。

## 五、验证

定向测试：

- `execution-controller.test.ts`：token 到线停止、未设上限不误杀；8 条通过。
- `agent-capability-policy.test.ts`：五个岗位都有工具与三类上限；builder 能写、critic 只能读/验收；worker 保留写与命令能力；任务预算只能收紧不能放大；停用岗位拒绝派活；5 条通过。
- `agent-spawn.test.ts`：卡外工具（`review_verdict`、`tool_search`、`agent_spawn`、`kb_search`）不出现在 builder 子 Agent 工具表；token 超限任务 failed 且落 `budget_exhausted`；20ms 时长超限即使模型事后返回也 failed；10 条通过。
- `agent-review.test.ts`：验收员工具目录仍只含只读验证与结论工具；5 条通过。
- `tool-search.test.ts`、`agent-plan.test.ts`：无白名单调用行为不变；共 16 条通过。

定向 TypeScript 子图检查通过（`NODE_OPTIONS=--max-old-space-size=3072`）。

## 六、边界与后续

- 硬 allowlist 只过滤现有工具目录，不会凭空生成工具；插件/MCP 工具如果要给岗位，必须把真实工具 id 登记进卡。
- 岗位卡仍是“岗位级”约束；任务显式预算只能收紧。需要更细的单任务工具子集时，可在 `agent.spawn` 再增加工具子集参数，但不能突破岗位卡。
- 成本预算暂不硬停，因为没有统一单价与计费口径；`used_cost_micros` 可先由调用方写入。
- 前端暂未新增预算告警条；当前通过任务行 `error` 和团队事件 `budget_exhausted` 已可审计，控制台可在后续版本读取。
