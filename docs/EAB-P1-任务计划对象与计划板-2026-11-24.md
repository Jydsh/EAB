# EAB P1：任务计划对象与计划板（AGT-08）

日期：2026-11-24
状态：代码接入完成，定向测试与真实浏览器验收通过；全仓类型检查受主机内存限制未完成

## 1. 目标

复杂任务不再只靠一段开头说明“我会分几步”，而是把计划变成可持久化、可版本化、可逐步推进的一等对象：

- 模型先用 `plan.write` 写计划，再按步骤调用 `plan.step`。
- 前端在对话右侧看到计划标题、版本、完成数和每一步状态。
- 刷新页面、换设备重开会话后，仍能从会话接口取回同一份最新计划。
- 同一任务改计划时保留旧版本，不直接覆盖历史。

## 2. 数据模型

迁移：`packages/storage/migrations/0093_agent_plan.sql`

`agent_plans`：

- `id / plan_key / company_id / user_id / session_id / trace_id`
- `title / status / version / supersedes_id`
- 同一 `company_id + plan_key + version` 唯一。
- 计划状态：`running | succeeded | failed | cancelled`。

`agent_plan_steps`：

- `id / plan_id / seq / title / detail / owner / status / note / run_id / updated_at`
- 同一 `plan_id + seq` 唯一。
- 步骤状态：`pending | running | done | failed | skipped`。

服务层：

- `packages/server/src/agent-plan.ts`
- `writeAgentPlan()`：首次自动生成 `plan_<random>`；同一 `planKey` 再写生成 `version + 1`，旧计划和旧步骤保留；同一计划不能跨用户/会话改写。
- `updateAgentPlanStep()`：按 `planKey` 或当前会话最新计划定位，更新步骤状态和备注，并重新推导总状态：有失败即 `failed`，全部 done/skipped 即 `succeeded`，否则 `running`。
- `getCurrentAgentPlan()`：返回当前会话最新计划、步骤和最近 10 个版本摘要。
- 单份计划上限 `AGENT_PLAN_MAX_STEPS = 7`。

## 3. 工具入口

`packages/server/src/routes/tools.ts`

| 工具 | 函数名 | 参数 |
| --- | --- | --- |
| `plan.write` | `plan_write` | 可选 `planKey`、可选 `title`、必填 `steps`（1–7 项，含 `title/detail/owner/status`） |
| `plan.step` | `plan_step` | 可选 `planKey`、必填 `seq`、必填 `status`、可选 `note` |

- `steps` 同时兼容数组和 JSON 字符串，避免模型把数组序列化成字符串后失败。
- 两个工具使用 `SC.AGENT_TOOL_INVOKE`，`dangerous: false`，并发 `write`，锁键按公司 + planKey。
- 计划工具只对主 Agent 下发；子 Agent 的 `allowPlanTools=false`，不入核心工具清单。
- 即使子 Agent 通过其他方式拿到工具定义，执行入口也会拒绝 `agent:*` 会话，避免把计划写进隔离的子 Agent 会话。

## 4. 对话事件与读取接口

`packages/server/src/routes/chat.ts`

- `AgentEvent` 新增 `{ type: 'plan'; plan: AgentPlanView }`。
- `plan.write` / `plan.step` 成功后，额外 emit `plan` 事件。
- SSE 转发层补上 `event.type === 'plan'`，否则事件只停留在后端，前端收不到。
- 工具摘要压缩为“计划 vN｜x/y 步完成 · z 步失败”，不把整段计划 JSON 塞进工具卡。
- 新增 `GET /api/chat/sessions/:id/plan`：校验 `chat:use`，确认会话属于当前用户且未删除，返回 `{ plan }` 或 `null`。

系统提示新增“任务计划｜先计划再执行”：

- 3 步以上、跨文件/资料、调研 + 实现 + 验收、需要派子 Agent 时先写计划。
- 单步问答、简单查询、单文件小改不写。
- 同一任务复用同一 `planKey`。
- 每步开始/完成/失败/跳过及时更新。
- 回复只说明计划已更新，不重复抄全文。

## 5. 前端计划板

文件：`packages/server/public/chat.html`、`chat.js`、`chat.css`

- Agent 团队面板顶部新增计划板：标题、`vN · x/y 步`、总状态、步骤列表、备注。
- 步骤状态用圆点和颜色区分：完成绿色、进行中蓝色、失败红色、跳过灰色。
- `applyPlan()` 处理 SSE 事件，`loadSessionPlan()` 打开历史会话时通过接口补拉。
- 计划存在但还没有子 Agent 时，右侧工作台也会出现“Agent 团队”入口。
- 新建会话和切换会话时先清空旧计划，避免串会话。
