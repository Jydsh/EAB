- 验收口径：数据类问题只允许实测通过的模型；没有可用实测模型时必须明确降级，不能静默换弱模型

## 1. 为什么不是“健康检查通过就能答数据题”

健康探测只能证明端点活着，压测只能证明并发能力；两者都不能证明模型会算数、会按条件取数、会在明细里不漏行。数据类回答一旦算错，用户很难从一段流畅文字里发现。

因此 AGT-18 新增的是一张独立的**任务实测结论表**，把“这个模型在这类任务上是否可信”与“这个模型现在是否在线”分开记录。管理员必须提交测试证据，空口点“通过”会被后端拒绝。

## 2. 数据模型

迁移文件：`packages/storage/migrations/0099_model_task_verifications.sql`

表 `model_task_verifications`：

| 字段 | 含义 |
| --- | --- |
| `id` | 记录 id，重测不换 id |
| `company_id` | 公司隔离 |
| `model_id` | 模型 id；插件模型没有 `models` 行，所以**不做外键** |
| `task_kind` | 任务类型，目前只有 `data.qa` |
| `status` | `passed` / `failed` / `revoked` |
| `verified_at` | 本次结论时间 |
| `verified_by` | 登记人 |
| `evidence` | 测试证据；`passed` 必填且至少 4 字符 |
| `notes` | 失败原因或补充说明 |
| `expires_at` | 可选有效期；为空表示长期有效 |
| `created_at` / `updated_at` | 审计时间 |

约束与语义：

- `(company_id, model_id, task_kind)` 唯一：一个模型一类任务只保留当前结论。
- 重测覆盖状态、证据、有效期，但保留原记录 id 与 `createdAt`，历史审计靠 `appendAudit` 留痕。
- 只有 `status='passed'` 且 `expires_at` 为空或晚于当前时间，才算“当前有效”。
- 读取白名单时与当前可见模型目录求交；模型下线、插件卸载、角色被收回后，白名单自然失效。

## 3. 策略模块

文件：`packages/server/src/model-task-policy.ts`

- `MODEL_TASK_KINDS`：目前仅 `data.qa`，显示名“数据类问答”，说明覆盖统计、明细、排名、占比、查数与数字核对。
- `isDataQuestion(text)`：统一的数据问题判定。网页原 `wantsBusinessDataAnswer` 已改为直接调用它，避免两套口径。
- `verifiedModelIdsForTask(db, companyId, taskKind, now)`：返回当前有效 `passed` 模型 id 集合，过期自动排除。
- `saveModelTaskVerification(...)`：校验任务类型、状态与时间；`passed` 必须带证据，且有效期必须晚于当前时间。
- `dataQualityTierOf(row)`：输出 `data_verified / data_failed / data_expired / untested`。
- `dataModelDegradeNotice(modelName, reason)`：生成置顶降级提示，写明原因、实际模型名与“数字请人工复核”。
- `dataModelExplicitBlockedMessage(modelName, allowedNames)`：生成显式拒绝文案，列出可用模型，并说明“不做静默换模”。
- `resolveDataTaskModel(...)`：渠道（钉钉/飞书）统一选模。数据问题有白名单时只从已通过模型里挑；显式选了未实测模型直接阻断；没有白名单时允许回答但标记降级。

## 4. 选模与门禁

### 4.1 网页对话 `/api/chat/messages`

- 请求文本命中 `isDataQuestion` 时读取 `data.qa` 白名单。
- 白名单非空：
  - 自动选模只在“白名单 ∩ 当前身份可见模型 ∩ 对话端点 ∩ 图片能力”里选。
  - fallback 候选同样限制在白名单内，主模型失败后不会落到未实测模型。
  - 用户显式选了未实测模型：HTTP 400，`code=EAB_VALIDATION`，`details.task='data.qa'`、`details.modelId`、`details.allowedModelIds`，并给出可切换模型提示。
  - 图片场景额外过滤 `endpointKind==='chat'`，避免视觉能力命中非对话端点后选模为空。
- 白名单为空：
  - 不阻断回答，但 `dataPolicy.status='degraded'`，回答最前面加降级提示，写明原因和实际模型名。
- 白名单存在但当前身份没有可见的合规模型、或没有支持图片的合规模型：也降级并写明原因。
- 返回消息、SSE `done`、持久化 `meta` 都带 `dataPolicy`：
  `{ task, status, verifiedCount, selectedModelId, selectedModelName, reason }`。
- 演示 echo 路径同样加降级前缀，避免没有真实 Agent 时漏提示。

### 4.2 钉钉 / 飞书

- 渠道消息在自身选模处调用 `resolveDataTaskModel`，与网页同口径。
- 会话里显式 `/model` 选了未实测模型时，直接回复“没有通过数据类实测 + 可用模型”，不进入模型调用。
- 没有白名单时允许回答，正文置顶降级提示；`meta.dataPolicy` 同步落库。
- 故障转移候选、以及模型在同一轮内调用 `switch_chat_model` 可切换的模型列表，都裁到白名单内，避免“先选对、再被工具切到未实测模型”。

### 4.3 子 Agent / 任务图 / 后台任务

`runAgentTurn` 入口增加了最后一道兜底：只要本轮最后一条用户消息是数据问题，公司又登记过白名单，而当前 `modelId` 不在白名单内，就直接抛 `EAB_VALIDATION`，不调用模型。

这条兜底不负责自动换模，作用是**失败关闭**：任何绕过入口选模的路径（子 Agent 独立选模、任务图执行器、后台恢复轮）都不能静默用未实测模型答数据题。子 Agent 若被分到未实测模型，会显式失败并在任务状态里暴露，而不是产出看似正常的错误数字。

### 4.4 实测通过模型直通，不再压住正文

`model-task-policy.ts` 的 `shouldRunDataAnswerGate({ text, modelId, verified })` 统一判定：

- 普通问题：不需要门禁。
- 数据问题 + 当前模型在有效 `data.qa` 白名单内：**不需要门禁**，正文从第一个字就通过 SSE / 钉钉卡片刷新，不再等整段生成和数字核对。
- 数据问题 + 当前模型未登记、未通过、已过期，或系统完全没有白名单：**仍走交付前门禁**，先压住正文，核对取数证据和数字后再放行。

网页、钉钉、飞书三处入口都用这个函数决定是否传 `completionGate`。这样“已登记可信模型”不会为了核对多等几十秒，而弱模型仍不会被静默放出去。模型如果后来出现数字问题，管理员应把它在控制台标记为“未通过/撤销”，门禁会自动恢复。

另外，正文“逻辑上可流式”不等于“界面上一定逐段出现”。有两条兜底：

- 工具失败恢复或门禁放行时压住的整段正文，服务端按总长度反推段大小（每段 6–60 字、共约 120 段），每段间隔 55ms 发送；约 1.5k 字正文回放约 6–7 秒，10k 字正文也不会拖到一分钟。
- 网页端把 `rawAnswer` 与已揭示长度解耦：正常 token 小增量直接显示；单个 delta 超过 120 字、或正文只在 `done` 里一次性回来时，切到逐字节奏（每帧约 4 字、约 130 字/秒），从 0 开始显示而不是直接 `innerHTML` 铺满。图表代码块在这段逐字显示期间会先显示已解析的数据点或“图表生成中…”，不会因为 JSON 还没闭合就把整条正文卡住。
- 收尾时如果服务端/数字门禁给出了另一份终稿，网页不再把旧前缀和终稿拼接，而是清空后从 0 重播，避免“前半段有字、最后一帧整段换稿”。已有历史消息打开时仍按数据库正文一次性渲染，这是回看，不是新一轮生成。


## 5. 控制台

接口：

- `GET /api/console/models` 增加 `taskKinds`；每个模型增加 `dataVerification` 与 `dataQualityTier`，原生模型和插件模型都覆盖。
- `POST /api/console/models/:id/task-verifications`
  - body：`{ taskKind, status, evidence, notes, expiresAt }`
  - `expiresAt` 收毫秒时间戳
  - 校验模型存在于原生模型或 `listAllPluginModels`
  - 写入后 `appendAudit`，`action='model.task_verification'`，`resourceType='model'`

界面：

- 模型行显示数据质量徽标：“数据实测”“数据未过”“实测过期”。
- 模型行新增“数据类实测”按钮，原生与插件模型都有。
- 弹窗展示当前结论、登记人、有效期；可选通过 / 未通过 / 撤销，填写测试证据、备注、有效期；“通过”在前端也强制至少 4 字符证据。
- 保存成功后 toast 并刷新模型列表。

## 7. 边界与风险

- `data.qa` 目前只有一类，粒度是“数据问答”，没有细分统计、明细、排名等子任务。
- “是否实测通过”依赖管理员提交证据，没有自动基准评测集；证据质量由审计留痕约束，不由系统自动判定。
- `passed` 默认长期有效；不填有效期就不会自动过期。对模型升级、量化版本变更，管理员需要主动重测或撤销。
- 数据问题正则是启发式，可能误判（把普通分析问句当数据题）或漏判（换个说法绕过关键词）。门禁是降低风险，不是数学证明。
- 子 Agent/任务图走兜底拒绝，不做自动改派；白名单过窄时会表现为任务失败，而不是自动找可用模型。这是有意选择：宁可显式失败，不静默降级。
- 插件模型没有 `models` 表行，模型卸载后靠“与可见目录求交”失效；如果插件重新安装并复用同一 `model_id`，旧结论会重新生效，需要管理员复核。

## 8. 管理员使用步骤

1. 控制台「模型接入」找到要用于数据问答的模型。
2. 点“数据类实测”，选择“通过”。
3. 填写测试证据，至少写清样本量、对照口径和差异处理，例如：
   “30 条考勤样本，28 条与源表完全一致，2 条为跨天班次，已人工核对”。
4. 如有版本窗口，填写有效期；到期后自动从白名单移除。
5. 保存后模型行显示“数据实测”。
6. 网页、钉钉、飞书的数据问题会优先使用这些模型；已通过模型直接流式回答，未通过/未登记模型仍先过交付门禁；没有白名单时回答会带降级提示；显式选未实测模型会被拒绝。
