# EAB 对话模型切换需求（2026-11-11）

## 1. 目标

让员工在对话过程中切换模型，不再只能去设置页或重新发起会话；切换范围只能是当前身份有权限使用的模型，包含：

- EAB 数据库里的原生模型；
- 插件通过 `ctx.llm.registerAdapter` 注入的 `plugin:` 模型；
- 插件通过 `registerConfigurableProviders` 声明的通道名称。

插件模型不需要落 `models` 表，也不允许为单个插件写死适配。

## 2. 用户可见行为

### 2.1 模型选择入口

1. 输入框左侧模型按钮仍可直接点选。
2. 在对话输入框发送 `/model`：
   - 当前会话没有模型时，展示当前身份可用的模型列表；
   - 当前会话已有模型时，先显示当前模型，再展示可切换列表。
3. 发送 `/model <名称或标识>` 直接切换；也接受自然表达：
   - `切换到 <模型>`
   - `切换模型到 <模型>`
   - `换成 <模型>`
   - `使用 <模型> 模型`
4. 发送 `/auto`、`/自动` 或 `换成自动`，恢复自动选择。
5. 模型列表只来自 `/api/chat/models`，该接口已按 `chat:use`、`model:use` 和角色可见性过滤；前端不自行读取全量模型表。

### 2.2 切换后的会话行为

- 切换只影响当前会话，后续消息使用新模型；其他会话不受影响。
- 会话刷新或重新打开后，仍保留本会话最后选择的模型。
- 选择“自动”时清空会话固定模型，由服务端按当前权限和默认用途路由重新选择。
- 新会话默认使用自动选择；自动选择沿用现有规则：`chat.default` 用途路由 → 第一个原生模型 → 模型目录第一个。`chat.default` 指向插件模型时，自动选择也会使用插件；网页和渠道共用这套规则。
- 每条回答仍显示实际使用的模型名；自动选择的回答标记“自动选择”。

### 2.3 渠道机器人对话

配置好的渠道机器人（当前入站实现为钉钉单聊；飞书/企微复用同一命令模块）支持与网页一致的对话内切换：

1. 发送 `/model`、`/模型`、`切换模型`：返回当前会话模型和当前身份可用模型列表。
2. 发送 `/auto`、`/自动`：清空当前渠道会话的固定模型，恢复自动选择。
3. 发送 `/model <名称或标识>`、`切换到 <模型>`、`切换模型到 <模型>`、`换成 <模型>`、`使用 <模型> 模型`：切换并持久化到该渠道会话。
4. 命令不调用模型、不扣月度对话额度；普通消息才进入额度校验和模型调用。
5. 模型切换只影响当前渠道会话；同一员工再次与机器人对话会沿用该会话的 `chat_sessions.model_id`。
6. 模型列表与切换候选只来自 `loadModelCatalog + visibleModelsFor`，并额外校验 `chat:use`、`model:use`；无权/不存在的模型统一提示“没有找到你有权限使用的模型”，不返回候选中的无权模型。
7. 会话里保存的模型下线或角色不再可见时，下一轮自动回退并清空 `model_id`；选择固定模型后发图片，若该模型没有视觉能力，提示先切换支持图片的模型，不静默换模型。

### 2.4 失败与权限

- 目标模型不在当前可用列表内：提示“没有找到你有权限使用的模型”，不展示无权模型的存在信息。
- 目标模型已下线、被停用或角色不再可见：
  - 当前会话回退到自动选择；
  - 明确提示原模型已不可用，不静默使用其他模型。
- 会话不属于当前员工：返回 404，不泄漏会话内容。
- 插件模型 upstream 失败：沿用现有 `EAB_UPSTREAM` 502 错误，不伪装成模型切换失败。

### 2.5 插件模型健康检测与自动容灾

插件同步过来的模型默认参与对话，但插件上游的免费额度、限流、超时和服务可用性会变化。为了避免员工每次选中一个不可回复的模型才看到报错，增加以下行为：

1. 服务进程启动后立即探测一次插件模型，之后默认每 30 分钟探测一次；探测使用最小请求（`请只回复两个字：可用`，`maxTokens 8`，默认 15 秒超时），不写入对话内容。
2. 探测失败或真实对话遇到上游/限流/冲突类错误的插件模型，标记为“暂时不可用”，从 `loadModelCatalog` 的对话候选过滤；控制台仍可看到插件模型及其只读信息，不把健康状态当成模型下线。
3. 探测成功或后续真实调用成功时恢复健康，重新进入对话候选；健康状态只存在进程内存，不落库，重启后重新探测。
4. 每次对话仍优先使用用户/会话已选的模型。该模型失败时，按“当前员工仍有权限、且本轮能力匹配（图片消息要求视觉能力）”的候选依次自动接替。
5. 机器人渠道在模型调用期间缓冲回答：失败模型的半截回答丢弃，接替模型成功后只下发一份完整回答，并提示“当前模型「X」暂时不可用，已自动切换到「Y」”。
6. 网页对话同样复用备用模型列表；流式回答只有在失败前尚未输出任何内容时才自动重试，避免两个模型的半截回答拼在一起。
7. 只有当前员工所有有权限且能力匹配的候选都失败时，才返回“当前有权限的模型都暂时无法回复，请稍后再试。”；只有一个候选时保留原上游错误。
8. 用户固定选过模型的会话发生接替后，接替模型写回该会话的 `model_id`；自动模式保持 `NULL`，下一轮仍由服务端自动选择。
9. 健康检测只影响对话候选，不改变员工权限、模型绑定和控制台配置；无权模型永远不会进入候选或备用列表。

## 3. 服务端契约

### 3.1 会话模型偏好

`chat_sessions` 新增 `model_id`（可空文本）：

- `NULL` 表示自动选择；
- 非空表示当前会话最后选择的模型，允许 `plugin:` 模型 ID；
- 不建立到 `models` 表的外键，因为插件模型不存在于 `models` 表。

`POST /api/chat/sessions/:id/model`

请求：

```json
{ "modelId": "plugin:our-free-model:mimo-v2.6-flash-free" }
```

- `modelId: null` 表示恢复自动选择；
- 必须同时具备 `chat:use`、`model:use`；
- 只接受 `/api/chat/models` 同一套可见性结果中的模型；
- 会话必须属于当前员工且未删除；
- 返回 `{ modelId, modelName }`。

### 3.2 发送消息时的模型解析

`POST /api/chat/messages`：

1. 请求显式传 `modelId` 字符串：校验可见性后使用，并写入会话 `model_id`。
2. 请求显式传 `modelId: null`：使用自动选择，并清空会话 `model_id`。
3. 请求未传 `modelId`：读取会话 `model_id`；该模型仍可见则使用，否则回退自动选择并清空。
4. 有图片附件时，自动选择优先带视觉能力的模型；显式选择的模型不支持图片时返回 400，提示切换模型。

### 3.3 渠道机器人

`packages/server/src/channel-model-command.ts` 是渠道可复用的纯函数模块：

- `planChannelModelCommand(text, models, currentModelId)` 只读取调用方传入的可见模型；
- 钉钉 `handleDingTalkMessage` 在额度校验前拦截命令，命中后直接返回文本，不建卡片、不调用 `runAgentTurn`；
- 命中切换命令时更新该员工渠道会话的 `chat_sessions.model_id`；
- 普通消息按 `chat_sessions.model_id` 取模型：仍可见则使用，不可见则清空并回退自动；图片消息额外要求视觉能力；
- 钉钉入站额外校验 `chat:use`、`model:use`，与网页 `POST /api/chat/messages` 保持一致。

### 3.4 插件模型健康与故障转移

`packages/server/src/model-health.ts`：

- 进程内健康表按 `companyId -> modelId` 保存 `{ healthy, checkedAt, failures, lastError }`，不落库；
- `filterHealthyModels(companyId, models)` 过滤不可用插件模型；
- `shouldMarkModelFailure(error)` 只把上游、限流、冲突类错误计为不可用；权限、参数、未找到、用户中止不标记；
- `probePluginModel(companyId, modelId, timeoutMs)` 通过 `callPluginModel` 发最短请求；成功恢复、失败标记；
- `startModelHealthMonitor(companyId, { intervalMs, timeoutMs })` 首轮立即探测，之后串行探测当前插件模型，`timer.unref()`，返回停止函数。

`runAgentTurn` 增加：

- `fallbackModelIds?: string[]`：备用候选，由调用方根据当前员工可见模型生成；
- `bufferModelEvents?: boolean`：渠道开启，失败时丢弃该次缓冲并恢复文本/推理，成功后一次性下发；
- `onModelFailover?: (change) => void`：通知调用方从哪个模型切到哪个模型；
- 返回 `usedModelId`、`usedModelName`、`fallbackFromModelId`，调用方按实际模型写会话、消息、审计和渠道事件。

`loadModelCatalog` 对插件模型执行健康过滤；原生模型不受该内存健康表影响。

## 4. 验收

- `/api/chat/models` 同时包含原生与插件模型，且只返回当前员工可见的模型。
- 对话输入 `/model` 展示的列表与 `/api/chat/models` 完全一致，不出现无权模型。
- 选择插件模型后发送消息，请求进入 `callPluginModel`；上游失败返回 `EAB_UPSTREAM`。
- 关闭页面重开会话，模型选择仍为该会话保存的模型。
- 选择自动后，会话 `model_id` 为空，回答标记自动选择。
- 无权模型 ID 直接调用切换接口返回 403，且不写入会话偏好。
- 渠道机器人发送 `/model` 只返回当前可见模型；发送 `/model <可见模型>` 后，同一渠道会话的 `chat_sessions.model_id` 写入；发送 `/auto` 后清空。
- 渠道会话已保存模型不可见时，下一轮不调用该模型，并清空 `model_id`。
- 不可回复的插件模型在健康探测失败后不再出现在 `/api/chat/models`；恢复健康后重新出现。
- 首选模型真实回复失败时，备用模型接替并返回完整回答；渠道不出现两个模型的半截拼接。
- 所有有权限且能力匹配的候选都失败时返回聚合错误“当前有权限的模型都暂时无法回复，请稍后再试。”。
- 故障转移后，固定模型的会话 `model_id` 写为接替模型；自动模式仍为 `NULL`。
- 既有控制台模型页、插件通道、用途路由行为不回归。

## 5. 暂不做

- 飞书/企微尚未有机器人入站实现；本轮先把命令模块做成渠道无关，等入站链路接入时直接复用，不伪造渠道能力。
- 插件模型进入 `model_routes` 显式用途绑定；仍受现有外键边界限制。
- 跨会话共享模型偏好；模型选择绑定到会话，不绑定到员工全局设置。
- 健康检测周期、超时和探测 prompt 暂不做控制台可配置项；当前使用代码默认值。
- 故障转移后“临时接替、下一轮恢复原选择”未实现；固定模型会话会写回接替模型，避免继续撞同一个不可用模型。
