# EAB 高级 UI 动效规范

- 版本：2026-11-24（动效层 v1）
- 适用范围：EAB 员工工作台、管理控制台、登录页、官网/产品故事页，以及后续 React 前端
- 相关代码：`packages/server/public/ui-motion.css`、`ui-motion.js`、`ui-motion-lab.html`
- 相关技能：`eab-ui-motion`

## 1. 这份规范解决什么问题

用户的原话是“把视频里的设计理解成技能，EAB 项目按这个设计，后续网页设计更高级”。

这句话真正要解决的不是“加多少动画”，而是三件事：

1. **把模糊的“高级感”拆成可命名的动作。** 设计说“这里高级一点”，开发不再靠猜；大家直接说“给运行卡加 Border Beam，2.8 秒循环，只描边”。
2. **把动效变成状态语言，而不是装饰。** 运行、等待、成功、失败、推荐、过期，各自有固定动作，跨页面一致。
3. **把标准写进工程。** 统一 token、opt-in 协议、性能底线、无障碍降级和验收清单，后续页面按同一套规则扩展。

因此，本规范的目标不是让 EAB 所有元素都动起来，而是让**该动的地方动得准确，不该动的地方保持安静**。

## 2. 三层模型

### 2.1 功能反馈层（必须克制、必须快）

用于按钮、开关、输入、加载、成功/失败、权限不足。

- 时长：100–200ms。
- 效果：按压、Hover Lift、Spring、Shimmer、Ease Out。
- 目标：让用户确认“点到了 / 正在处理 / 成功了 / 失败了”。
- 禁止：3D 倾斜、滚动叙事、跑马灯、文字解码。

### 2.2 结构层（解释层级和空间）

用于页面区块、卡片列表、弹窗、抽屉、侧栏、运行卡。

- 时长：160–360ms；滚动显现可用 600–700ms。
- 效果：Scroll Reveal、Stagger、Spotlight、Border Beam、Tilt（仅产品卡）。
- 目标：让用户知道“先看哪里 / 哪些是一组 / 哪个正在运行”。
- 禁止：同一屏 3 个以上循环动画；所有卡片统一上浮。

### 2.3 叙事层（只出现在愿意阅读的页面）

用于登录页、官网、产品故事、运营看板、空状态首屏。

- 时长：单段不超过 900ms；滚动叙事可跟随滚动进度。
- 效果：Scrolltelling、Parallax、Marquee、Typewriter、Text Scramble、Count Up。
- 目标：讲清“为什么、然后呢、下一步”。
- 禁止：工作台表格、审批页、聊天主界面整屏钉住。

## 4. 统一 token

定义在 `ui-motion.css` 的 `:root`：

```css
--eab-ease-out: cubic-bezier(.16, 1, .3, 1);
--eab-ease-spring: cubic-bezier(.34, 1.56, .64, 1);
--eab-dur-1: 100ms;  /* 按压、悬停 */
--eab-dur-2: 160ms;  /* 微交互 */
--eab-dur-3: 240ms;  /* 转场 */
--eab-dur-4: 360ms;  /* 小面板 */
--eab-dur-5: 640ms;  /* 滚动显现 */
--eab-stagger-step: 55ms;
--eab-lift: -4px;
--eab-spot-color: rgba(15, 107, 92, .16);
--eab-beam-color: rgba(45, 212, 191, .75);
```

规则：

- 页面/组件不再自己写 `0.2s ease`、`0.3s ease-in-out` 这类散装值。
- 只有叙事层允许超过 640ms；单段不超过 900ms。
- `prefers-reduced-motion: reduce` 下所有时长归零，循环动画关闭。

## 5. 组件协议：`data-motion`

只在需要动效的元素上写，不全局自动挂载。

```html
<!-- 单一主效果 -->
<article class="mem-card" data-motion="lift">...</article>

<!-- 组合：聚光灯 + 边缘流光 -->
<div class="agent-run-card" data-motion="spotlight beam">...</div>

<!-- 错峰列表 -->
<div class="mem-list" data-motion="stagger">...</div>

<!-- 数字递增 -->
<b data-motion="count" data-count-to="1280" data-count-duration="1500">1,280</b>
```

运行时行为：

- `reveal`：首屏元素自动跳过；首屏以下进入视口才动画。
- `stagger`：给子元素写 `--eab-i`，按 55ms 错峰；超过 8 项时仍可用，但建议直接显示。
- `spotlight / magnetic / tilt`：只在精细指针设备启用；触屏不做。
- `parallax`：监听滚动，位移限制 ±90px。
- `count / typewriter / scramble`：进入视口后执行一次；`scramble` 可点击重播。
- `marquee`：自动克隆一组内容，克隆标记 `aria-hidden="true"`，悬停暂停。
- 动态插入的弹窗、消息、列表由 MutationObserver 自动接管；也可手动 `window.EABMotion.init(container)`。
- MutationObserver 必须保持长期引用（模块级变量），不能只放在 `observe()` 局部变量里；否则会被垃圾回收，后续弹窗不再触发动效。
- 动态节点扫描应同步执行，不要用 `requestAnimationFrame` 做节流；后台或遮挡窗口的 rAF 可能被暂停，导致新弹窗永远停在初始隐藏态。

为什么用 opt-in：EAB 是企业工作台，表格、表单、长文占大多数。自动给所有元素挂动画会制造噪音，也会让性能不可控。

## 7. 性能与无障碍底线

### 7.1 性能

- 只动 `transform` 和 `opacity`；禁止 `width / height / top / left / margin`。
- 循环动画不超过 3 个/屏；每个循环必须有明确语义。
- `will-change` 只给正在动的元素，动画结束移除。
- 列表超过 8 项不做长错峰；滚动中不做高开销计算。
- 移动端降低光斑尺寸、关闭 tilt、减少 parallax 位移。

### 7.2 无障碍

- `prefers-reduced-motion: reduce` 下关闭非必要动画，信息仍可读。
- 键盘焦点必须可见；动效不能拦截点击、不能改变点击目标位置。
- **输入框（`input` / `textarea` / `select`）聚焦只用边框色变化表达，不绘制 `outline` 或外圈 `box-shadow`；按钮、链接、复选框仍保留可见键盘焦点环。** 深色外环不作为输入框焦点语言。
- 文字解码/打字机必须保留 `aria-label` 或最终完整文本。
- 跑马灯必须悬停暂停，克隆内容 `aria-hidden="true"`。
- 触控目标不小于 36px；磁吸只给精细指针。
- 不用闪烁（>3Hz）表达状态；错误不能只靠红色动画。

## 8. 评审方法

每个动效改动按这个模板写一句话，写不出来就不做：

```text
场景：<页面/组件> 在 <状态> 时。
主效果：<16 种之一>，负责 <解释什么>。
辅助效果：<最多 1–2 个>，负责 <解释什么>。
参数：<时长> / <缓动> / <位移或透明度>。
边界：<哪里不用>；减少动态效果时 <降级方式>。
验收：<在哪个真实页面看什么>。
```

评审顺序：

1. 先问“这个状态是否必须被看见”。不是，就不加。
2. 再问“有没有更便宜的表达方式”（文案、颜色、图标、进度条）。
3. 再看“是否只用一个主效果”。
4. 最后看性能、reduced-motion、键盘、移动端。

## 12. 第 4 批记录（后台高频页：先修布局，不加动效）

本批没有新增动效。部门、审批记录、知识库的问题都是信息层级和容器高度，先让页面“静止时就看清楚”，再考虑是否加转场。

- **审批记录不铺满整屏**：审批记录是数据阅读页，不是画布。`.approval-shell.is-records` 改为 `height:auto; min-height:0`，记录面板随行数收缩；1 条记录时内容高度约 305px，不再从顶部拉到页面底部。打开详情时仍由详情内容决定高度，保持主表与详情同一行。
- **节点属性标题分层**：「节点属性 · 开始」作为弱标签，「发起申请」作为节点名，先回答“这是什么面板”，再回答“当前是哪一步”；不新增闪烁、脉冲或高亮，避免在流程编辑器里制造视觉噪音。
- **部门头部操作归位**：更换负责人属于业务动作，不放进统计卡；头部按钮按「更换负责人 → 编辑部门 → 删除」排列，删除只在非根部门出现。用位置表达危险级别，不用红色动画表达。
- **知识库文档标题合并**：`文档` 与 `文档说明` 徽标同一行，用 flex 对齐；这是排版修正，不加 reveal 或 stagger。
- **成员管理不改**：表格、角色列、部门权限概览已稳定；没有明确状态需要解释时，不为了“有改动”而加动效。

## 19. 第 11 批补充规则（对话首屏与失败反馈）

- **历史内容首屏不能依赖动画时钟**：`animation ... both` 会让消息在动画起始帧保持 `opacity:0`。对话页在重载/后台恢复时，如果 `document.timeline.currentTime` 停在 0，整段历史就会只剩空白背景。历史消息必须直接落在最终态，只有本轮新追加的消息才播放入场过渡。
  - 实现约定：`.msg` 不再默认挂动画，改为 `.msg.is-new`；`appendMessage()` 历史路径默认 `animate:false`，实时用户消息、实时 AI 回合和重新挂回的运行中节点显式调用 `markMessageNew()`。
  - 兜底：`markMessageNew()` 在 650ms 后移除 `is-new`；即使动画被环境冻结，也不会长时间停在透明起始帧。
  - `prefers-reduced-motion: reduce` 下 `.msg.is-new` 禁用动画。
- **失败反馈用“状态角标”，不要用“全宽空卡”**：图表类型不支持是局部能力提示，不是一张需要占满气泡宽度的内容卡。`.answer-chart.is-error` 使用 inline-flex 的 28px 高角标，保留完整错误文本和 14px 的 `!` 标识；`.answer-chart.is-loading` 仍保持原来的加载块。
- **失败角标不加循环动效**：红色只表达状态，不做 Pulse、闪烁、抖动或自动展开；连续失败按自然行排列，不阻断阅读。

## 33. 第 25 批补充规则（员工端响应式）

- **侧栏抽屉只做位移与遮罩淡入**：`≤1120` 时 `.chat-side` 用 240ms `transform` 从左侧移入，遮罩 `eab-side-scrim-in` 180ms 只变透明度并带 1.5px 背景模糊；宽度、内容和内部区块不做高度或逐项动画，首屏默认收起，不能让会话入口先被隐藏。

## 34. 第 26 批补充规则（AI 回答解剖）

- **回答层级是静态重排**：`process-stack`（思考 → 工具 → 团队进度）在前、`answer-block`（结论 → 来源/附件 → 错误）在后，只改变 DOM 顺序和间距；不加入场 stagger、滚动揭示或整块淡入，先给过程依据，再让结论落地。
- **来源折叠只切显隐**：`.kb-source-panel` 由 `kb-source-head` 切换 `is-collapsed` 与 `aria-expanded`，chevron 只做 150ms 旋转；来源正文限高 220px 并提供滚动，不播放高度展开、逐条 stagger 或内容淡入。
- **附件 chip 不做批量入场**：附件条在回答收尾时一次生成，chip 不做 stagger、不做缩放；仅可打开文件保留 160ms 边框/底色 hover，键盘焦点用 `:focus-visible` 外环。
- **失败是内容替换，不是抖动**：错误卡直接渲染在 `.answer-error`，不使用 shake、闪烁、自动重试倒计时或逐字出现；错误详情折叠沿用原生 `details`，展开不做高度动画。
- **重试按钮只表达可执行动作**：重试、切换账号、重新生成都是静态按钮；生成中不脉冲、不禁用动画表达状态；重试触发后由既有流式状态接管，旧错误卡直接移除，不做退出动画。
- **手动停止不是失败动画**：停止卡使用 `is-interrupted` 静态配色，保留已生成正文；不播放“失败”红光、抖动或音效。
- **复制反馈走统一 toast**：复制成功/失败只调用 `banner()`，按钮自身仅把 `data-tip` 改为“已复制”1.4s，不做缩放、打勾弹跳或颜色循环；`prefers-reduced-motion` 下附件 hover 过渡关闭。

## 35. 第 27 批补充规则（无障碍与动效）

- **焦点环是静态可读层，不做呼吸/脉冲/闪烁**：`:focus-visible` 统一为 2px 白色内环、1px offset、4px 深色外环；深色图片灯箱改白色外环；焦点出现和消失都即时完成，不加入场缩放、颜色循环或阴影动画。
- **输入区焦点只由容器表达**：`.composer-box textarea` 的 `focus`/`:focus-visible` 不叠加全站 outline 和 box-shadow，由 `.composer-box:focus-within` 的绿边/外发光表达焦点。
- **浮层入场不能让首屏内容隐身**：Modal 和遮罩可以保留既有 160–220ms 淡入/位移，但 `opacity` 起始值不得为 0 且依赖动画才显示；共享焦点守卫在 rAF 后再做 60ms 二次校准，避免点击收尾把焦点还给触发按钮，同时不抢用户已移入浮层的焦点。
- **焦点锁不改变视觉状态**：Tab/Shift+Tab 只在浮层内部循环，不播放方向提示、描边扫光或滚动动画；关闭/移除后直接回焦触发元素，不做“焦点飞回”动画。
- **页签切换只做状态切换**：roving tabindex、方向键/Home/End 只改选中态和 `tabIndex`，不新增滑块指示器、横向位移动画或逐项 stagger；颜色/底色过渡沿用现有 150ms 级别，减少动效下归零。
- **图标按钮命名不产生视觉噪点**：`×` 读作“关闭”、`⋯` 读作“更多操作”，只写 `aria-label`，不增加可见文字、角标或 tooltip 动画。
- **减少动效是硬约束，不是组件自愿项**：全局 `@media (prefers-reduced-motion: reduce)` 把 `animation-duration`/`transition-duration` 压到 `0.01ms`，`animation-delay`/`transition-delay` 归 0，`animation-iteration-count` 为 1，`scroll-behavior` 为 `auto`；覆盖第三方组件和后续新增动画，不依赖每个组件自己声明。
- **实测口径**：CDP 模拟 reduce 后 `matchMedia('(prefers-reduced-motion: reduce)')=true`，按钮过渡从 `0.12s` 降到 `1e-05s`，延迟 0；测试后恢复 `no-preference`。焦点环实测键盘聚焦“工作台”时 `:focus-visible=true`，深色 4px 外环可见。
- **资源版本**：`ui-overlay.css/js?v=20261125uiP27G`、`chat.js?v=20261125uiP27G`、`app.js?v=20261125uiP27G`；`chat.css?v=20261125uiP27I`（输入区焦点环修正），`app.css` 仍 `v=20261123uiP23C` 系列。
