# EAB P1 · AGT-12 产物交接标准化

> 版本：`2026.11.23.04`（本轮未升级版本号）
> 日期：2026-11-24
> 审计来源：`docs/EAB-Agent框架对照审计与能力建设需求-2026-11-23.md` 的 AGT-12
> 验收口径：产物带 checksum/preview/mime；父 Agent 不重复读全文；A2A 产物可预览。

## 1. 本轮解决的问题

审计时产物登记已经有 `mime_type / size / checksum / source / uri / preview` 字段，但真实链路里有四个缺口：

1. **工作区产物预览不可靠**：`preview` 仍是可选值，子 Agent 不主动填写时，父 Agent只看到一个文件名。
2. **外部 URI 产物信息不完整**：`checksum` 为空、MIME 固定成 `text/uri-list`、`size=0`，父 Agent 无法判断类型和版本。
3. **A2A 文件产物信息缺失**：只有带 `name` 的文件才有 preview；有 `bytes` 的文件不计算真实大小和内容校验和；多个 file part 还可能生成重复 id。
4. **父 Agent 看不到完整产物清单**：完成事件、后台唤醒、历史摘要和 `agent_wait` 返回都只给名称或 fileId，父 Agent 只能重新 `workspace_read` 读整份文件才能确认内容。

AGT-12 的目标不是再加一个“产物字段”，而是让产物在**登记、跨 Agent 交接、A2A 回传**三个环节都自带可核对的元数据和预览。

## 2. 产物标准化规则

### 2.1 MIME

- 工作区 / 云空间产物：**扩展名优先**，再回退 `workspace_files.mime`，最后回退 `application/octet-stream`。
- 外部 URI 产物：调用方传入的 `mimeType` 优先，其次按名称扩展名推断，最后才回退 `text/uri-list`。
- 历史产物解析时，缺 MIME 的旧数据补 `application/octet-stream`，避免新清单出现空字段。

扩展名优先是为了修真实缺陷：真实库里的 `workspace_files.mime` 可能仍是 `text/plain`，会把 `.md` 产物误标。因此 `.md` 现在稳定识别为 `text/markdown`。

### 2.2 checksum

- 有本地内容的产物（工作区、云空间、A2A 内联 bytes）：`sha256:<64 位>`，是**文件内容校验和**。
- 只有远端地址、没有本地内容的产物（外部 URI、A2A 仅 URI）：`ref-sha256:<64 位>`，是 `uri + 名称 + MIME` 的**引用指纹**。
- 两种前缀明确区分，父 Agent 不会把“地址指纹”误当成“内容指纹”。

### 2.3 preview

入库统一压成单行，最多 500 字。自动生成规则：

| 来源 | 自动预览 |
| --- | --- |
| 工作区 / 云空间文本 | 最多读取开头 1024 字节，生成最多 240 字实际内容 |
| 工作区 / 云空间二进制 | `文件：名称（mime，大小）` |
| 外部 URI | `外部产物：名称（mime）` |
| A2A 内联文本 | 最多读取 512 字节，生成最多 240 字实际内容 |
| A2A 内联二进制 | 带 MIME、大小和“内联内容”的元数据摘要 |
| A2A 仅 URI | 带 MIME 和“有下载地址”的元数据摘要 |
| A2A 无 URI 无 bytes | 内部稳定引用 + “未提供下载地址” |

文本预览只读固定长度，不整文件读取；调用方显式传 `preview` 时仍可覆盖自动结果。

### 2.4 size

- 工作区 / 云空间：真实文件字节数。
- A2A 有 `bytes`：解码 base64 后的真实字节数。
- 外部 URI / A2A 仅 URI：保持 `0`，不伪造大小，由预览和 checksum 说明“只有地址”。

## 3. A2A 产物

`summarizeA2ATask()` 现在对每个 file part 都生成产物引用，不再只处理有 `uri` 的文件：

- 有 `bytes` 时解码 base64，计算真实大小和 `sha256:` 内容校验和；
- 文本类内联 bytes 生成实际内容预览；
- 只有 `uri` 时生成 `ref-sha256` 引用指纹，预览说明有下载地址；
- 无 `uri` 且无 `bytes` 时使用 `a2a:artifact/<taskId>/<artifactId>/<index>` 作为内部稳定引用；
- 一个 artifact 有多个 file part 时 id 用 `artifactId:index` 保证唯一；
- text/data parts 仍并入 `resultText`，不伪装成文件产物。

**当前边界**：A2A 只有 URI 时不主动下载远端内容，因此无法给出远端内容校验和；这是有意控制网络副作用，不是遗漏。

## 4. 父 Agent 交接

### 4.1 清单格式

新增 `artifactBrief()` / `artifactManifest()`，单条产物摘要包含：

`名称｜MIME｜大小｜checksum｜fileId 或 uri｜A2A 标记｜预览`

一个任务最多展开 6 条，超出显示“另有 N 个产物未展开”，避免把唤醒消息撑爆。

### 4.2 接入位置

- 后台子 Agent 完成唤醒：`artifactHint` 使用完整 manifest；
- 历史任务摘要：产物从“只列名称”改为完整 manifest；
- 本批任务有产物时，唤醒消息追加【产物交接】规则，明确要求父 Agent 直接引用清单，不要用 `workspace_read` 重读整份文件；
- 多 Agent 系统提示新增第 9 条：完成事件和 `agent_wait` 会带产物清单，汇总时直接引用；
- `agent.publish_artifact` 的 `done` 事件 payload 增加 `artifactCount` 和最多 6 条产物元数据；
- `agent_wait` 返回的每条任务增加 `artifactCount` 和最多 6 条产物元数据，有事件时附带 `artifactHint`；
- 独立验收员提示在产物列表后追加“预览：…”，验收员不必只凭文件名判断。

### 4.3 真实缺陷修复：子 Agent 登记产物报“任务不存在”

联调时发现子 Agent 调 `agent.publish_artifact` 会报 `任务不存在：task_xxx`。根因不是产物表，而是团队 ID 不一致：

- 子 Agent 的 `runAgentTurn` 原来按 `sessionId=agent:<runId>` 新建团队，得到 `teamId=session:agent:<runId>`；
- 但 `agentTaskId` 指向父团队的 `session:<sessionId>` 里的任务行；
- 产物登记按“当前团队 + 任务”查，自然查不到。

修复方式：

- `runAgentTurn` 新增可选 `agentTeam?: AgentTeamStore`；
- 有 `agentTeam` 时直接复用父团队实例和 `teamId`，不再新建；
- 子 Agent 调用处和独立验收员调用处都传 `agentTeam: opts.team`。

这个修复由新增集成测试真实触发并通过，不是只靠测试替身。

## 8. 已知边界与后续

1. **A2A 仅 URI 不主动下载**：只生成引用指纹和地址预览，不拉取远端内容。若后续需要远端内容校验，必须单独设计下载超时、大小上限和域名白名单，不能直接放开。
2. **外部 URI 的 MIME 由调用方或扩展名决定**：服务端不发起 HEAD 探测，避免登记产物时产生额外网络副作用。
3. **`agent_wait` 的新字段目前没有单独的端到端测试**：当前由同一份 `waitTaskViews()` 构造，字段结构与已经测试的 done payload 一致；后续可在真实会话验收时补一条。
4. **本轮未升版本、未 commit、未 push**：版本号变更和 GitHub 同步按用户确认后再做。
