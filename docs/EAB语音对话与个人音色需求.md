# EAB 语音对话与个人音色需求（2026-11-23）

## 1. 目标

让员工可以在网页工作台和钉钉机器人里用语音对话，并让 EAB 用语音回答；系统只提供一个默认音色，员工可以在网页里保存多段自己的声音描述，并选择其中一段作为默认回复音色。

语音只改变交互方式，不改变对话模型、权限、知识库、会话历史和月度额度规则。

## 2. 范围

### 2.1 本期实现

1. 网页工作台只保留“语音对话”一个语音入口，支持持续录音、自动断句、转写和自动发送。
2. 网页工作台在“语音对话产生的回答”完成后自动播放语音，并保留重播入口。
3. 钉钉机器人收到语音消息后，先正常回复文字/卡片，再补发一条钉钉原生语音消息。
4. 内置音色只保留一个“系统默认”（`S0`），不在界面暴露 `S1`–`S9`。
5. 员工可以在“设置 → 语音 → 我的音色”里新建、编辑、删除多段声音描述，并选择一段作为默认回复音色。
6. 网页和钉钉共用同一份个人声音配置，修改后下一轮生效。
7. 网页语音入口除点击外，还支持在设置页开启“语音唤醒”后，用当前助手名字直接唤醒；管理后台修改助手名字后，已打开的页面无需刷新即可换成新唤醒词。

### 2.2 本期不做

1. 不采集、不保存员工本人录音，不做声纹克隆；需要本人声音克隆时另立需求并单独做授权与留存。
2. 不把语音音频写入 `chat_messages`，历史消息只保留文字；刷新页面不恢复旧语音，只保留重播入口不可用的文字回答。
3. 不做真正的实时流式 ASR、也不做声学双工通话；连续语音对话采用“前端 VAD 自动断句 + 一次性 ASR + 流式 TTS”，并提供显式“打断播报”按钮与开口自动停播。
4. 不改动现有 ASR/TTS 用途路由的管理后台配置方式。

## 3. 用户可见行为

### 3.1 网页工作台

1. 输入框左侧只保留一个语音对话图标按钮，不再显示“语音对话”文字，也不再提供单次“语音提问”按钮。
   - 未启用时按钮只显示图标，不显示边框和底色；启用后显示品牌色边框和底色。
   - 未配置 `asr.default` 或浏览器不支持录音时，入口不显示。
   - 麦克风权限被拒绝时进入失败状态，提示检查浏览器权限，可重试或退出。
2. 点击“语音对话”进入连续语音会话：
   - 持续监听麦克风，前端用 VAD 自动检测开口与停顿；停顿约 1.15 秒自动结束本句并转写、发送。
   - 单句录音最长 30 秒；10 秒没有检测到开口时结束本句并回到聆听，不发送空消息。
   - 助手回答边生成边按句合成、流式播放；每个声音方案第一次使用时生成固定参考音频，之后每句都用同一参考做 Voice Clone，保证不同回答也是同一个人；全文持续播报，不再截断字数。
   - 播报结束自动回到聆听，形成连续多轮；播报期间检测到用户开口，自动停止播报并立即回到聆听。
   - 播报中点“打断”立即停止音频并开始下一轮聆听；聆听中点“结束这句”提前结束录音。
   - 未配置 TTS 或员工关闭语音回复时，回答只显示文字并进入“已暂停”，不自动续听。
   - 进入语音对话后，键盘输入或带附件发送会自动退出语音对话，避免两种输入方式互相抢占。
3. 语音对话发出的用户消息标记为“语音来源”，只用于决定是否自动语音回复。
4. 回答正常流式显示。回答完成后：
   - 如果 `tts.default` 可用、个人语音回复开启，调用语音合成并自动播放。
   - 浏览器阻止自动播放时，在回答下方显示可点击的“播放语音”按钮，不报错。
   - 合成失败时保留完整文字回答，只提示“语音回复生成失败”，不重试、不影响下一轮。
5. 只有语音来源的消息触发自动语音；键盘输入、文件、图片、云空间引用触发的回答仍只显示文字。
6. 回答下方保留“播放语音”入口，可重复播放本次回答；入口不写入历史消息。
7. 语音回复默认开启。员工关闭后，语音对话仍会转写并正常回答，只是不再自动合成语音。
8. “设置 → 语音唤醒”开启后，页面持续监听麦克风，转写开头出现当前助手名字即进入语音对话：
   - 名字后带指令时，去掉名字后的剩余内容直接作为第一条消息发送；只喊名字或只打招呼则进入正常聆听。
   - 唤醒采集与正式语音对话互斥；进入对话、页面隐藏、退出页面、助手播报时停止采集，退出对话后自动恢复待命。
   - 管理后台保存助手名字后，已打开的页面通过 SSE 热更新 AI 名字、唤醒提示和语音按钮标题，不需要刷新。
   - 语音唤醒默认关闭，只在员工显式开启后运行；开关状态只保存在当前浏览器。

### 3.2 钉钉机器人

1. 钉钉语音消息有 `recognition` 时直接用识别文字；没有时继续走现有 `asr.default` 下载转写。
2. 转写成功后走完整对话链路，文字/卡片回复规则不变。
3. 文字/卡片发送成功后，再发一条钉钉原生语音消息。
   - 语音内容取本轮最终回答的可朗读文本，去掉 Markdown、代码块、表格、链接地址和引用标记。
   - 连续语音与网页重播均朗读完整回答；代码块、表格等不适合朗读的内容跳过，文字回答始终完整保留。
   - 语音使用当前员工选中的声音方案；没有个人方案时用系统默认。
4. 语音发送失败不改变文字回复结果，不要求用户重发；只记录日志。
5. 文字消息、图片消息、文件消息、`/model` 等命令不触发语音回复。
6. 钉钉语音回复不写入会话的额外消息，不重复占用一条 assistant 历史。

### 3.3 个人音色设置

入口：网页工作台“设置 → 个人设置 → 语音回复 / 我的音色”。

1. “语音回复”开关：开启/关闭自动语音回复。
2. “我的音色”弹层只显示一个内置音色“系统默认”，不再展示 `S0`–`S9` 让员工逐个挑选。
3. 员工可以新建多段“我的声音”：
   - 每段包含名称（可选，最多 40 字）和声音描述（必填，最多 200 字）。
   - 新建后自动成为当前默认，并显示在“我的声音”列表。
   - 每段声音都可以编辑、删除；删除当前默认时自动回到系统默认。
   - 点击列表中的某一段，再点“保存”，即可切换默认回复音色。
4. 描述示例： “低沉、沉稳的男声，语速稍慢，像可靠的技术同事”。
5. 使用员工账号派生的固定随机种子，保证同一员工、同一段描述生成的声音稳定。
6. 编辑页提供“试听”，试听文本固定为“你好，我是 EAB 企业智能助手，很高兴为你服务。”
7. 保存后只影响当前员工，网页和钉钉下一轮同时生效。
8. 非本人无权读取或修改他人的声音方案。
9. 本期不采集本人录音，也不做声音克隆；所有“我的声音”都来自文字描述。
10. “语音唤醒”位于“语音回复”和“我的音色”之间；开启/关闭只写浏览器 `eab.voiceWake.enabled`，不写服务端，不影响同一账号在其他设备上的设置。

## 4. 服务端契约

### 4.1 数据表

`user_voice_profiles`：

| 字段 | 类型 | 说明 |
|---|---|---|
| company_id | TEXT | 公司 |
| user_id | TEXT | 员工 |
| voice | TEXT | 固定 `S0`，只作为系统默认的底层音色 |
| active_voice_id | TEXT | 当前使用的方案：`default` 或某个声音方案 ID，默认 `default` |
| instructions | TEXT | 兼容旧数据，保留空字符串；生效描述从声音方案读取 |
| enabled | INTEGER | 是否自动语音回复，1/0，默认 1 |
| updated_at | INTEGER | 毫秒时间戳 |

主键 `(company_id, user_id)`。无记录时按默认值读取，不要求提前插入。

`user_voice_presets`：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | 方案 ID，`vp_` 前缀 |
| company_id | TEXT | 公司 |
| user_id | TEXT | 员工 |
| name | TEXT | 声音名称，最多 40 字，同名自动追加序号 |
| instructions | TEXT | 声音描述，最多 200 字 |
| created_at | INTEGER | 创建时间 |
| updated_at | INTEGER | 更新时间 |

按 `(company_id, user_id)` 隔离；员工可以保存多条，但只有一个处于使用中。

### 4.2 音色解析

`resolveVoiceProfile(db, companyId, userId)`：

- 读取个人记录；没有记录返回 `{ voice: 'S0', activeVoiceId: 'default', instructions: '', enabled: true }`。
- `activeVoiceId` 为 `default` 时描述为空；否则读取对应声音方案的描述。
- 方案已被删除时回退系统默认，不阻断对话。
- `seed` 不落库，由 `companyId:userId` 做 SHA-256 后取 32 位整数，保证稳定。
- 描述最多 200 字，名称最多 40 字；不把任意字符串直接传给 TTS 端点。

### 4.3 接口

`GET /api/me/voice`

- 返回：

```json
{
  "enabled": true,
  "activeVoiceId": "default",
  "instructions": "",
  "voices": [
    { "id": "default", "name": "系统默认", "instructions": "", "builtin": true, "active": true },
    { "id": "vp_xxx", "name": "稳重技术同事", "instructions": "低沉、沉稳的男声", "builtin": false, "active": false }
  ],
  "defaults": { "enabled": true, "activeVoiceId": "default" },
  "speechAvailable": true
}
```

- `speechAvailable` 取决于 `tts.default` 是否解析到可用模型。
- 只返回当前登录员工自己的配置和声音方案。

`PATCH /api/me/voice`

请求：

```json
{ "enabled": true, "activeVoiceId": "vp_xxx" }
```

- 两个字段都可选；只更新传入字段。
- `activeVoiceId` 只能是 `default` 或当前员工自己的方案 ID。
- 返回保存后的完整配置与声音列表。

`POST /api/me/voice/presets`

请求：

```json
{ "name": "稳重技术同事", "instructions": "低沉、沉稳的男声，语速稍慢" }
```

- 名称为空时自动使用“我的声音”并追加序号；描述必填，最多 200 字。
- 新建成功后自动设为当前默认。
- 返回完整配置与声音列表。

`PATCH /api/me/voice/presets/:id`

- 可单独修改 `name`、`instructions`，也可同时修改。
- 只能修改当前员工自己的方案；不存在时返回 404。
- 若修改的是当前默认，下一轮立即使用新描述。

`DELETE /api/me/voice/presets/:id`

- 删除当前员工自己的方案。
- 删除的是当前默认时，自动把 `activeVoiceId` 切回 `default`。
- 返回删除后的完整配置与声音列表。

`POST /api/me/voice/preview`

请求：

```json
{ "voiceId": "default", "instructions": "低沉、沉稳的男声，语速稍慢" }
```

- `instructions` 非空时按这段草稿试听，用于保存前预览；为空时读取 `voiceId` 对应方案。
- 不保存配置，只合成固定试听文本。
- 返回 `{ mime, audio: "data:audio/...;base64,..." }`。
- 未配置 `tts.default` 返回 400 + 提示。

`POST /api/chat/speech`

- 保持现有契约，新增使用当前员工选中的声音：
  - `voice` 固定传 `S0`；
  - `instructions` 取当前默认方案的描述；
  - `seed` 取个人稳定种子；
  - 文本仍截断到安全长度。
- 仍然只要求 `chat:use`。

`POST /api/chat/transcribe`

- 保持现有契约，网页录音继续使用 data URL。
- 返回文字、模型 ID、模型名。

### 4.4 TTS 调用

`callSpeech` 增加可选参数：

```ts
{ voice?: string; instructions?: string; seed?: number; format?: 'mp3' | 'wav' | 'opus' }
```

- 请求体增加 `instructions` 和 `seed`，仅在非空/非零时发送。
- 默认格式改为 `mp3`，网页直接播放，钉钉转码前也以 mp3 为中间格式。
- 供应商返回的 `content-type` 与实际文件头不一致时，以文件头为准修正 `mime`。

### 4.5 钉钉语音出口

新增 `sendDingTalkVoiceToUser`：

1. 用 `ffmpeg-static` 把 mp3/wav 转成 OGG/Opus、48 kHz、单声道、32 kbps。
2. 调用钉钉 `POST /media/upload?type=voice` 获取 `media_id`。
3. 调用 `POST /v1.0/robot/oToMessages/batchSend`：
   - `msgKey: "sampleAudio"`
   - `msgParam: { mediaId, duration }`
   - `duration` 为 OGG 末页 granule 位置换算的毫秒数，无法计算时按文本长度估算。
4. 上传或发送失败抛出上游错误，调用方只记录日志，不回滚文字回复。
5. 音频超过钉钉媒体上限时拒绝发送，文字回答保留。

## 5. 失败与边界

| 场景 | 行为 |
|---|---|
| 未配置 ASR | 网页“语音对话”入口不显示；钉钉语音提示管理员配置转写 |
| 未配置 TTS | 网页语音对话仍可用，回答只显示文字；设置页提示未配置语音合成；钉钉只回文字 |
| 录音权限拒绝 | 提示浏览器权限，不进入录音循环 |
| 转写为空 | 不发送，回到聆听并提示重新说 |
| 单句录音超过 30 秒 | 自动结束本句并转写 |
| 10 秒未检测到开口 | 结束本句并回到聆听，不发送空消息 |
| 合成超时/失败 | 文字回答保留，提示语音生成失败 |
| 浏览器禁止自动播放 | 显示“播放语音”按钮 |
| 钉钉语音发送失败 | 文字/卡片保留，只记日志 |
| 用户关闭语音回复 | 网页与钉钉都不自动发语音 |
| 个人配置损坏或非法 | 回退系统默认，不阻断对话 |
| 声音描述为空 | 拒绝保存，提示填写描述 |
| 当前声音方案被删除 | 自动切回系统默认 |
| 回答超长 | 按句合成并用同一锚点克隆，持续播报全文；代码块、表格跳过；文字完整 |

## 6. 验收标准

1. `GET /api/me/voice` 对没有个人记录的员工返回系统默认、空描述、开启状态，且只显示一个内置音色。
2. `POST /api/me/voice/presets` 新建后自动成为当前默认，再次读取名称和描述一致。
3. `PATCH /api/me/voice` 能在系统默认和已保存方案之间切换，且不影响其他员工。
4. `PATCH/DELETE /api/me/voice/presets/:id` 能修改或删除方案；删除当前默认后自动回到系统默认。
5. `POST /api/me/voice/preview` 能按草稿描述或已保存方案返回可播放音频。
6. 网页只显示“语音对话”一个语音入口；开启后录音能转写并自动发送，回答完成后自动播放语音。
7. 浏览器禁止自动播放时仍出现可点击的“播放语音”按钮。
8. 网页键盘输入不触发自动语音。
9. 钉钉发送语音消息后，先收到文字/卡片，再收到语音气泡；语音使用当前员工选中的声音。
10. 钉钉语音发送失败时文字回复仍完整。
11. 关闭个人语音回复后，网页与钉钉都不再自动发语音。
12. `pnpm typecheck` 通过；声音方案创建、切换、删除、描述上限与 OGG 时长计算的单测通过。
13. 设置页开启语音唤醒后，说当前助手名字能进入语音对话；名字后带“帮我查天气”这类指令时直接发送，只喊名字时不发送空消息。
14. 管理后台修改助手名字并保存后，已打开的聊天页无需刷新，AI 名字、唤醒提示和语音按钮标题同步变化。
15. 关闭语音唤醒或退出语音对话后，唤醒采集停止；页面隐藏、切换会话和助手播报期间不会自我唤醒。

## 7. 已知限制

1. 对员工只展示一个“系统默认”，`S0`–`S9` 仅作为底层 TTS 参数保留，不出现在界面上。
2. 专属声音描述依赖模型的音色设计能力；描述写得越具体，生成结果越稳定。
3. 同一个员工的不同声音方案共用个人种子，主要靠描述区分音色；如果需要更强区分度，后续再按方案派生独立种子。
4. 钉钉原生语音要求 OGG/AMR，服务端需要随包携带 `ffmpeg-static` 做转码；没有该二进制时语音回复失败，文字不受影响。
5. 本期不做录音克隆，避免引入声纹授权、样本留存和删除流程。
6. 语音唤醒依赖浏览器持续持有麦克风，只适合网页前台打开时使用；锁屏、页面隐藏、切到后台标签页时不会唤醒。
7. 唤醒词是当前助手名字，ASR 可能把字母或生僻字写成同音字；已对常见单字母同音字做别名展开，极端口音或麦克风较差时仍可能识别失败。
8. 助手名字改短、改长或改成生僻词后，唤醒命中率取决于 ASR 对该名字的识别；可在设置页提示中看到当前实际唤醒词。

## 9. 连续语音对话 v1.1（2026-11-23，历史记录）

### 9.1 交互与状态机

前端状态字段 `state.voiceConversation`：

| 字段 | 说明 |
|---|---|
| active | 是否处于连续语音会话 |
| phase | `idle` / `listening` / `transcribing` / `thinking` / `speaking` / `paused` / `error` |
| generation | 会话代次，用于丢弃退出或重开后的迟到结果 |
| sessionId | 开启时的会话，切换会话自动退出 |
| resumeTimer | 播报结束后的续听定时器 |
| maxMs / noSpeechTimeout | 单句最长 30 秒 / 无开口 10 秒 |
| calibrating / threshold / level | 前 650ms 校准环境噪声，阈值取 `max(0.01, min(0.06, 平均噪声 × 2.6))` |

状态流转：

1. 点击“语音对话” → `listening`，请求麦克风并开始录音。
2. VAD 检测连续 3 帧超过阈值判定开口；开口后静默 1.15 秒且已说满 800ms，自动结束本句 → `transcribing`。
3. 转写成功 → `thinking`，文本写入输入框并走原聊天发送链路。
4. 回答产生 `delta` 时按句切分并立即入队；每句都用当前声音的固定参考音频克隆，段内与跨回答保持同一说话人。
5. 文本与音频都结束 → 260ms 后回到 `listening`；播报失败或被浏览器拦截 → `paused`，由用户点“继续聆听”。
6. 播报中用户开口或点“打断” → 停止音频、中止当前 TTS 流并立即续听；转写/回答失败 → `error`，可重试或退出。

## 9.7 跨回答固定音色与按句流式播报（2026-11-23）

### 9.7.1 问题与结论

员工听到的“每条回答像换一个人”，不是同一段音频内部的漂移，而是**不同回答之间**换了说话人。根因在 Breeze-TTS-2 的 Voice Design：每次推理都会重新设计说话人，同一条声音描述、同一个 `seed` 只能让结果接近，不能保证跨请求是同一个人。只把整段回答合成一次，只能保证这一条回答内部一致；下一条回答仍会重新设计。

最终方案分两层：

1. **固定锚点**：每个声音方案第一次使用时，用官方 Breeze 的 Voice Design 生成一段 24kHz 参考音频和它的精确文字稿，存入该声音方案。之后所有请求都带 `ref_audio + ref_text` 做 Voice Clone。
2. **按句流式**：LLM 每吐出一句完整中文就入队；前端串行请求 `/api/chat/speech/stream`，服务端用同一段锚点克隆。这样边生成边播，且每一句、每一条回答都锁定同一个说话人。

设置页试听和对话页共用同一个锚点：试听的 `voiceId` 就是当前启用声音且描述未改时，先取该声音的固定锚点再克隆试听文本；只有试听“尚未保存的新描述”时才走一次性的 Voice Design。因此保存后，设置页听到的就是对话页之后会用的同一个人。

### 9.7.2 上游选择

| 端点 | 能力 | 结论 |
| --- | --- | --- |
| `http://192.168.1.3:8100/v1`（旧 shim） | `/audio/speech/stream` 裸 PCM 24kHz；无 batch；`ref_audio`、`prompt_speech` 均被忽略，只有 `instruction` 生效 | 只能做 Voice Design，不能跨请求锁音色，不再作为最终 TTS 端点 |
| `http://192.168.1.3:8110`（官方 Breeze TTS API） | `/v1/audio/speech` multipart，支持 `text`、`instruction`、`cfg_scale`、`ref_audio`、`ref_text`、`seed`；`/v1/audio/speech/batch` 最多 128 条 | 采用官方 8110，克隆路径固定 `cfg_scale=1` |

官方克隆实测：

- `ref_audio` 与 `ref_text` 必须成对；`cfg_scale=1` 时克隆成功，`cfg_scale=4` + 参考音频会 500。
- 参考音频必须是 24kHz 单声道 WAV。SAPI 生成的 16kHz WAV 直接做 clone 会 500；模型自己生成的 24kHz WAV 稳定成功。
- 女声参考 F0 214.3 → 克隆 216.2；男声参考 F0 102.1 → 克隆 105.7。说明真正生效的是参考音频，不是用 description 假装。
- 同一句文本连续合成两次：输出字节数完全相同（218,880），F0 都是 258.1；不同句文本 F0 会随语调变化，但说话人音色保持同一锚点。
### 9.7.3 代理与存储

- `llm.ts` 新增 `isBreezeOfficialTts`：`model_key === 'breeze-tts-2'` 且 `base_url` 含 `:8110` 时走官方 multipart。
- `callSpeech`：官方分支返回 `audio/wav`，用 `pcmToWav` 给裸 PCM 加 24kHz 单声道 WAV 头；用于设置页试听、锚点生成。
- `/api/me/voice/preview`：当前启用声音且描述未改时先 `ensureVoiceAnchor`，再用同一锚点克隆固定试听文本；未保存的新描述不写锚点，保持一次性预览。
- `callSpeechStream`：官方分支直接透传 `res.body`，默认 24kHz；409/429 退避一次重试。
- `voice-anchor.ts`：按 `company + user + activeVoiceId + modelId + instructionsHash` 读锚点；没有就生成一次并写库。内存与并发锁保证同一声音首次只生成一次。
- `user_voice_presets` 复用 `0090` 的 `anchor_audio/anchor_text/anchor_model_id/anchor_updated_at`；系统默认音色用 `0091` 给 `user_voice_profiles` 增加同名字段。
- 锚点模型键存 `modelId|instructionsHash`；员工改“我的声音”描述后，旧锚点自动失效并重新生成。

### 9.7.4 前端实现

1. `feedVoiceSpeechStream(delta)` 累积文本，并按 `。！？!?；;` 与换行切句；超过 600 字无标点才硬切，避免拆开小数或日期。
2. 每个完整句子清洗 Markdown 后入队；`pumpVoiceSpeechStream` 串行消费，当前句还在播放时就开始合成下一句。
3. `playVoiceSpeechSegment` 读取 `/api/chat/speech/stream` 的 PCM，按小端 s16 转 Float32，用 24kHz `AudioBufferSourceNode` 按 `nextStart` 连续排程。
4. 首块预缓冲 `0.9s`；正常衔接时后续块提前 `0.16s` 排程；时间轴被网络/上游抖动吃穿时，重新攒 `0.2s` 再继续。
5. `endVoiceSpeechStream` 只补最后一段没有句末标点的文本，不再清洗整段后只合成一次。
6. `maybeFinishVoiceSpeech` 在“文本结束 + 队列空 + 所有 source 播完”后收尾，260ms 后自动续听。
7. `abortVoiceSpeechStream` 停所有 source、清空队列与未成句文本、abort 当前 fetch；退出语音、切会话、开口打断都走同一路径。

### 9.7.5 本轮验证

- `pnpm typecheck` 通过。
- 官方克隆同一文本两次：字节数与 F0 完全一致，证明跨请求同一说话人。
- EAB 三句测试文本走前端真实队列：`data-voiceRequests=3`、`data-voiceUnderruns=1`，三句都发起请求并播完回到聆听。

### 9.7.6 已知限制

1. 官方 8110 是单推理槽，逐句请求只能串行；20 字短句合成约 7–10s，而音频只有 3–4s，RTF > 1。多句长回答在句间仍可能出现一次 0.2s 左右的补齐停顿；已通过“当前句播放时预取下一句”把停顿压到最少，但无法做到完全无感。
2. 每个声音方案首次使用要多等一次锚点生成（约 5–10s）；之后读库，不再重复生成。
3. 锚点音频存 SQLite 的 base64 字段，单个约 200–400KB；当前个人声音数量有限，暂不做对象存储。
4. 8000 字以上极长回答会切多个请求，仍受上游单槽串行限制；语速与停顿取决于上游模型。
5. 设置页试听走 `callSpeech` 单次 WAV 路径，浏览器对 WAV data URL 的兼容性已按 Chrome 验证；其他浏览器仍需回归。
6. 开口打断阈值仍需真人、不同麦克风和外放音量下调参；扬声器回放无法替代真人测试。

4. 只在转写开头匹配，避免回答正文里出现同音词就误唤醒；匹配后去掉名字，后半句直接作为第一条指令发送。
5. 名字后只跟“你好/您好/在吗”等问候时，不把问候当指令发送，只进入正常聆听。
6. 进入正式语音对话、页面隐藏、退出页面、助手播报时暂停唤醒采集；退出对话或播报结束后，如果开关仍开启，自动恢复待命。

### 9.8.2 名字更新链路

1. 管理后台 `PUT /api/console/company/assistant` 保存名字/头像后调用 `publishChatEvent`，广播 `assistant` 事件，字段为 `companyId/name/avatarUrl/revision`。
2. `/api/chat/events` SSE 对公司内所有在线员工广播 `event: assistant`；其他聊天事件仍按公司 + 员工过滤。
3. 前端 `source.addEventListener('assistant')` 调用 `applyAssistantIdentity()`，更新 `state.assistant`、已渲染的 `.who-ai` 名字/头像、设置页唤醒提示和语音按钮标题，无需刷新页面。
4. 语音唤醒的别名缓存不单独保存；每次匹配都按当前 `state.assistant.name` 重新生成，因此改名后立即生效。

### 9.8.3 唤醒匹配

1. 匹配前做 NFKC、去空白/标点、去开头“嗯/喂/你好/请问”，兼容“小E”“E A B”“小易，”等 ASR 写法。
2. 单字母名字使用同音字表展开，例如“小E”可命中“小艺/小易/小依/小伊/小一”，但不会把不同读音的“小爱”当成同一个名字。
3. 纯中文名字在开头同长度窗口允许 1 个字差异，但只对 3 字以上名字放开；2 字名字必须精确命中，避免“小爱同学”这类不同名字误唤醒。
4. 近音/模糊命中只接受明确指令开头（帮我/打开/查/发/写/多少/怎么等）才把剩余文本作为第一条消息发送；否则只进入聆听。

### 9.8.4 本轮验证

- `node --check packages/server/public/chat.js` 通过。
- 设置页开启后提示“正在听，说‘小E’开始对话（页面打开时持续使用麦克风）”；开启态高亮，语音按钮出现待命光环，标题变为“开启语音对话（也可说‘小E’唤醒）”。
- 页面重载后按 `localStorage` 自动恢复待命；点击退出语音对话后自动恢复唤醒。
- 用 Windows SAPI 播放“小E，你好，请帮我查一下今天的天气”：ASR 把“小E”写成“小艺”，同音字别名命中，页面进入语音对话并发送“你好，请帮我查一下今天的天气”；状态条进入“正在生成回答…”，说明名字唤醒、去名字、首条指令发送链路已打通。
- 后台“连接与平台 → 公司设置 → 助手身份”把名字改成“小豆”并保存：已打开的聊天页不刷新，设置提示立即变为“正在听，说‘小豆’开始对话”，语音按钮标题同步变为“也可说‘小豆’唤醒”，已渲染的 AI 名字也变为“小豆”；改回“小E”后同样热恢复。
- 测试结束后关闭语音唤醒，`eab.voiceWake.enabled` 已移除，麦克风采集停止。

### 9.8.5 已知限制

1. 唤醒是持续麦克风能力，只在页面前台打开时有效；浏览器后台标签页、锁屏或系统休眠不会唤醒。
2. ASR 对字母、英文名和生僻字的识别不稳定；同音字表覆盖常见单字母，但不能保证所有口音和麦克风。
3. 当前唤醒判断只取转写开头，用户如果在助手播报刚结束后立即喊名字，可能被上一轮尾音干扰；播报期间已暂停采集，播报结束后恢复。
4. 唤醒词来自管理后台，后台改名会影响全公司所有开启语音唤醒的员工；没有按员工自定义唤醒词的入口。

## 9.9 连续音频播放与流式渲染降载（2026-11-23）

### 9.9.1 问题

1. 旧播放器对每个 HTTP PCM 块都新建 `AudioBufferSourceNode` 并按 `nextStart` 排程；块边界反复起停会产生咔哒声，网络抖动时还会重缓冲成断流。
2. 流式正文每约 28ms 全量重解析 Markdown 并滚到底部；长回答与语音同时进行时，主线程被渲染占满，会拖慢音频调度和页面响应。

### 9.9.2 实现

1. 新增 `packages/server/public/voice-pcm-player-worklet.js`，在 AudioWorklet 音频线程里持续消费 24kHz 单声道 s16le PCM；预缓冲 0.8s，起播/断流时做 6ms 淡入淡出，输出经 60Hz 高通去除低频嗡声。
2. `voicePlayback()` 优先创建 `sampleRate: 24000`、`latencyHint: 'playback'` 的 AudioContext；Worklet 模块加载失败或上下文不是 24kHz 时回退旧播放器。
3. `chat.js` 增加 `ensureVoiceWorklet`、`scheduleWorkletPcmChunk`、`handleVoiceWorkletMessage`；句末向 Worklet 发送 `end`，播放真正开始后才启动开口打断监测，`drained` 后才结束本轮播报。
4. 流式 Markdown 渲染在语音播报或语音对话期间降到 50ms（约 20fps），其他场景保持 28ms。
5. 服务端增加 `/voice-pcm-player-worklet.js` 同源静态路由，Worklet 模块不能通过普通脚本闭包加载。

### 9.9.3 验证

- `node --check`、`pnpm typecheck` 通过。
- 页面实际加载 `chat.js?v=20261123audio4`；AudioContext 采样率为 24000，Worklet 节点创建成功。
- 真机语音对话中 `#voice-dock` 的诊断字段为 `voiceEngine=worklet`、`voiceSampleRate=24000`、`voiceUnderruns=0`；播报结束能回到“正在聆听”，没有卡在“正在同步播报”。

### 9.9.4 已知限制

1. 上游仍是单推理槽、RTF 约 2.3–2.4；按句串行合成时，长句之间仍可能出现等待，不是播放器丢帧。
2. 只有拿到 24kHz 的 AudioContext 才会走 Worklet；极少数设备强制其他采样率时会回退旧播放器。
3. Worklet 解决的是播放侧块边界和主线程抖动；TTS 上游本身的音质/底噪不在本轮修复范围。

5. 语音唤醒开关只存浏览器，不随账号同步；换设备或清缓存后需要重新开启。
