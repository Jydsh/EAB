# EAB 登录后启动动画设计方案

状态：已实现（混合版 + 刷新轻启动）· 2026-11-15  
范围：管理控制台 `/admin`、员工工作台 `/chat`  
目标：登录成功后，从登录页进入系统时先看到一段有品牌感的启动画面；普通刷新时用同一启动层覆盖首屏加载的空白窗口，等应用真正可用后再淡出。

实现现状：生产代码已落地。两端共用 `boot-splash.js` 状态机与一次性规则；管理端默认 A+ 代码高定，员工端默认代码版、可在后台切换电影片头；全局配置与公司覆盖、片源上传/Range/删除接口均已接通。**正式品牌片源尚未配置**，所以当前两端实际都走代码版；上传正式 MP4 并在后台选 `film` 后，员工端即可播放电影片头。真实浏览器已验证管理端深色启动层、员工端真实登录启动层、电影片头预览、跳过、程序化删除与公司覆盖链路。

配套预览：`docs/eab-boot-splash-preview.html`，可直接打开体验 A+ 极简/代码版。预览页支持员工工作台 / 管理控制台切换、浅色 / 深色切换、重播启动、降低动效；预览节奏刻意放慢，便于观察，不代表最终实际时长。S 电影片头的播放链路已实现，原创品牌片源尚未制作/配置。

## 1. 参考对象：DSH 的启动画面

已在 2026-11-15 实际启动 `DSH NEXT`（2.0.22-next）观察启动首屏，画面特征如下：

- 全窗口铺满主题底色，深色主题下是近黑，没有图片背景。
- 画面正中只有三样东西：
  - `HARNESS` 字标：16px / 24px，字重 600，`letter-spacing: .08em`；
  - 20px 环形进度：2px 边框，外圈用 conic-gradient 画进度弧，0.8s 匀速旋转；
  - 一行 12px / 18px 的 `Loading plugins…`，低对比度。
- 启动状态是真实的：环形弧从 72° 起，按已激活插件数量增长到 288°；加载失败会切到错误态，不会永远转圈。
- 没有大 Logo 弹跳、没有粒子、没有全屏擦除。视觉重心只有一个字标、一个环、一句状态。

EAB 不需要照抄 `HARNESS`，但应沿用这套“少即是多”的启动语法：**全屏、居中、品牌字标、环形进度、真实状态、就绪即淡出**。

### 1.1 新的参考：dsh-video-skin / dsh-boot-animation 的“电影片头”

公开资料里，抖音视频提到的 `dsh-video-skin` 和同类 `dsh-boot-animation` 并不是 CSS 转圈，而是**整段视频片头**：

- `dsh-video-skin`：一段无声短片循环铺成聊天背景；另一段做**有声开机动画**，片尾**交叉溶解**进界面，点击画面随时跳过，零依赖。
- `dsh-boot-animation`：内置 4 段片头；在 DSH 客户端窗口内用 `position: fixed` 全幅覆盖；默认每次启动播一次；可跳过，播完自动关闭；支持用户自带视频；浏览器有声自动播放和全屏 API 都要求用户手势，因此它**默认静音播放**，点击一次才开声音并进入全屏；静音自动播放也被拒绝时，显示“点击播放”而不是黑屏。
- 它只能覆盖 DSH 客户端窗口，不能覆盖 Windows 任务栏或整个操作系统屏幕。

所以抖音视频里的“高级感”来自四件事：**有导演感的短片 + 声音 + 片尾溶解 + 可跳过/只播一次的产品化规则**，不是单靠 CSS 能做出来的。

结论：**能实现，但要先选片源路线**。直接复制 DSH 插件的内置片源不合适，EAB 需要原创短片或代码生成的“准电影感”画面。

| 版本 | 形态 | 建议时长 | 适合 | 成本/风险 |
|---|---|---|---|---|
| **S 电影片头版** | 原创 MP4 全屏播放，片尾淡出到首屏；声音默认静音、可点开 | 员工端 5–6s；管理端 3–4s | 最接近抖音参考，品牌记忆强 | 需要片源、媒体 Range 路由、音频策略、体积与弱网处理 |
| **A+ 代码高定版** | 光带/网格/字标分层，无视频、无声音 | 跟随真实加载，通常 0.2–1s；不设固定最短 | 轻量、任何分辨率都清晰、无素材依赖 | 高级感约 80%，不是电影镜头语言 |
| **混合版（建议）** | 管理端 A+ 代码高定，员工端 S 电影片头 | 跟随加载 / 5–6s | 后台克制、员工端有情绪；成本可控 | 需要两套素材和两套节奏，但共用一套状态机 |

“前后端各一套”按当前项目语境，我先理解为**管理后台 + 员工工作台两个页面各一套**。如果你指的是服务端进程启动时的终端动画，那是另一套 TUI，浏览器里看不到，需要单独做。

## 2. 设计目标与非目标

### 2.1 目标

1. 登录成功 → 进入系统之间有一个完整、可感知的过渡，不出现空白首屏。
2. 启动画面反映真实加载阶段，不做“假进度、假等待”。
3. 员工端和管理端共用一套启动组件，只换文案和时长参数。
4. 不改变登录接口、权限判断、会话逻辑，只改登录成功后的展示与首屏就绪信号。
5. 适配浅色/深色、桌面/移动端、`prefers-reduced-motion`，并保留失败/无权限时的正常错误页。

### 2.2 非目标

- A+ 代码版不做 3D 模型、粒子堆叠、视频背景和声音；S 电影版允许视频和声音，但按浏览器策略静音起播。
- A+ 版不强制“跳过”；S 版必须有跳过和声音开关，不能让用户被 5 秒片头锁住。
- 不做可点击的“跳过”按钮以外的复杂播放器控件；启动画面不是视频网站。
- 不为了动画强行延长登录时间。
- 不把启动画面做成第二个登录页，不展示用户身份、公司、模型等业务信息。

## 3. 视觉方案

### 3.1 推荐方案 A：DSH 同款极简启动屏（建议采用）

```text
┌────────────────────────────────────────────┐
│                                            │
│                  [ EAB ]                   │
│             企业智能体基座                 │
│                                            │
│                   ◯                        │
│              正在启动工作台…               │
│                                            │
└────────────────────────────────────────────┘
```

结构：

- 全屏 fixed 覆盖层，`z-index` 高于页面壳，背景使用当前主题底色，中央加一层很淡的品牌色径向光。
- 中央纵向排列：
  1. 40×40 圆角方形 EAB 标记，深绿底白字，复用现有 `.logo` 的品牌语言；
  2. 下方 12px 字距略宽的产品名“企业智能体基座”；
  3. 20px 环形进度；
  4. 12px 状态文字“正在启动工作台…”。
- 整体没有卡片边框、没有阴影、没有多余装饰；与 DSH 的静默底一致。

浅色：

- 背景 `#f4f7f6`，文字 `#14201d`，辅助文字 `#75837e`；
- 品牌色 `#0f6b5c`，径向光 `rgba(15, 107, 92, .08)`。

深色：

- 背景 `#0a0e14`，文字 `#e7eef7`，辅助文字 `#8b98a9`；
- 品牌色 `#5ee0c6`，径向光 `rgba(94, 224, 198, .10)`。

### 3.2 方案 B：Logo 组合动画（不推荐首版使用）

四个小方块从四角聚合成 EAB 方标，再进入环形进度。品牌感更强，但存在三个问题：

- 动画时间会被拉长，和“点完登录尽快进入”冲突；
- 需要额外设计 Logo 的分解形态，当前项目没有对应品牌资产；
- 容易变成装饰性动画，和 DSH 的“启动状态”语法不一致。

建议首版做 A；如果后续品牌发布会需要，再把 A 的静态标记替换成组合动画，不改启动状态机。

### 3.3 文案

管理端：

- 标题：`EAB 管理控制台`
- 初始状态：`正在进入管理控制台…`

员工端：

- 标题：`EAB 企业智能体基座`
- 初始状态：`正在启动工作台…`

阶段文案只在真实阶段变化时更新：

| 阶段 | 员工端 | 管理端 |
|---|---|---|
| 校验会话 | 正在验证登录状态… | 正在校验管理会话… |
| 加载配置 | 正在加载你的工作台… | 正在加载控制台配置… |
| 恢复首屏 | 正在恢复会话… | 正在准备控制台… |
| 就绪 | 准备就绪 | 准备就绪 |

如果某一阶段在 100ms 内完成，不强行停留；文案可以跳过，避免假等待。

## 4. 动效规格

### 4.1 进入

- 启动层首帧即完整呈现：方标、字标、副标题不做延时入场，避免页面加载很快时只看到半个 Logo。
- 背景分四层：极光渐变、透视网格、周期扫描带、细颗粒；网格用 72px 步长缓慢漂移，扫描带每 6.2s 从上往下扫过一次。
- 方标外圈有一条 9s 旋转的轨道环和两个小光点，方标表面有一次 1.2s 高光扫过。
- 字标 `EAB` 常显，字面带 4.8s 循环的薄荷色流光；页面另有一条 1.2s 的单向扫光。
- 环形进度从 72° 起始，视觉节奏按 1.6s 走到约 90%，首屏就绪时补到 288°；真实完成时间仍以加载为准。
- 环形持续 0.9s 匀速旋转，带 `drop-shadow` 微光；状态文字后有一个 1.25s 呼吸的在线光点，状态下方有一条流动细线。

### 4.2 退出

- 首屏就绪后触发 `EABBoot.ready()`；状态切到“正在进入…”。
- **登录跳转/完整启动**：代码版 `ready()` 到达后等待两帧确保启动层真正绘制，再开始 0.32s 淡出；电影版按片源播放，达到 `durationMax` 或视频结束时退场。
- **普通刷新轻启动**：强制走代码版，不请求 MP4、不播放声音；最短展示 480ms，`ready()` 到达后再淡出。超过 650ms 显示“正在加载组织与权限…”/“正在加载工作区…”，超过 2s 显示“网络较慢，仍在加载…”，2.6s 强制退场，避免无限遮挡。
- 后台预览需要可观察，单独用 1.2–2.4s，不进入真实登录流程。
- 电影版：片源缺失/解码失败回退代码版；它是有固定片长的独立片头，不是默认刷新过渡。
- `prefers-reduced-motion` 下淡出缩短到 0.18s；结束立即 `hidden=true` 并恢复页面滚动。
- 首屏在覆盖层下方已经完成布局，不做整体位移动画，避免内容跳动。

### 4.3 降低动态效果

`prefers-reduced-motion: reduce` 时，不能把启动层做成完全静止的静态图：

- 环形保留 1.6s 匀速旋转；这是“系统还在处理”的核心状态，不是装饰。
- 内容首帧完整显示；页面扫光、方标高光各保留一次 1.2s，不延时。
- 极光漂移、网格漂移、循环扫描带、字标流光、状态线流动全部停止，改为静态分层；轨道环保留静态位置。
- 退出淡出缩短到 0.18s。
- 这样既尊重“减少动态”，又不会让用户看到一张没有进度反馈的死图。

### 4.4 扫码登录过渡

员工端钉钉扫码确认后，不等 `exchange` 返回，立即在登录页中央铺同一套代码版启动层：

- 状态文字为“已识别扫码，正在登录…”，环形与字标照常运动。
- 状态行从贴底改为字标下方约 138px，整体留在页面中间；只对登录过渡生效，正常启动仍保持底部状态。
- 这一层不写 `eab.boot.seen`、不按电影片长播放、不响应跳过；`exchange` 成功后直接跳工作台，失败则 `finish(true)` 收起并显示二维码页错误。
- `exchange` 最长等 15 秒；超时按失败处理，避免无限遮挡。
- 重试时先清掉上一轮退场状态与计时器，再重新铺层，不叠层、不被上一轮定时器误关。

### 4.5 响应式

- 桌面：中央内容最大宽度 320px，整体垂直居中。
- 移动端（≤480px）：左右留 24px，字号不缩小；环形和状态文字保持可读。
- 横屏矮窗口：内容整体上移 4%，避免状态文字贴底。

## 5. 触发与状态机

### 5.1 推荐触发规则

**登录成功后播放完整片头；已登录用户在新标签页冷启动可按配置播放一次；同一标签页普通刷新播放轻启动代码动画，不重播完整片头。**

原因：

- “登录后”是用户明确要求的场景，保留完整片头和可跳过/声音能力；
- 已登录用户从书签打开工作台，也是一次真正的启动，仍保持品牌开场；
- 同一标签页刷新虽然不重播完整片头，但刷新到首帧之间仍有真实空白，必须用轻启动覆盖，不能直接露白。

实现的优先级与边界：

- `sessionStorage['eab.boot.next'] = 'admin' | 'chat'`：登录成功跳转前写入；命中时播放完整片头；
- `playOn=always`：仍按配置播放完整片头；`playOn=new-session` 首次访问播完整片头，后续刷新走轻启动；
- 其余已登录刷新走轻启动：只加载启动层 DOM/CSS，不请求 MP4、不播放声音；
- 轻启动最短 480ms、应用 `ready()` 即退场、2.6s 兜底；普通刷新不写一次性标记，不需要“刷新去重”。
- 如果 `sessionStorage` 不可用，登录跳转的回退仍可用 URL `?boot=1`，不影响刷新轻启动。

如果只想“登录后播放、冷启动不播放”，把冷启动分支关掉即可，组件不用重写。

### 5.2 状态机

```text
idle
  └─ 命中一次性标记 → booting
       ├─ phase(text, progress) → booting
       ├─ ready() → leaving → idle（移除覆盖层）
       ├─ beginLogin(text) → login-transition（中途铺层，状态居中，等待跳转或 finish(true)）
       ├─ fail(message) → failed → 1.2s 后 leaving
       └─ finish(true) → idle（立即收起，回到登录/错误页）
```

约定：

- `ready()` 可以重复调用，只生效一次。
- `phase()` 只在覆盖层存在时更新，不抛错。
- `finish(true)` 用于“未登录 / 会话失效 / 扫码失败 / 强制回登录页”，必须立即隐藏覆盖层。
- `beginLogin(text)` 用于扫码确认后的登录过渡：不写一次性标记、不等电影片长、不响应跳过；成功后直接跳转，失败由调用方 `finish(true)` 收起。
- `fail()` 用于首屏加载失败：覆盖层显示错误文案 1.2s，然后让用户看到页面自己的错误页，不永久遮挡。
- 15s 安全兜底：仍未收到 `ready()` 时，把状态改成“启动较慢，仍在加载…”，不强行移除，避免把未完成的页面暴露给用户。

## 6. 技术实现方案

### 6.1 新增文件

- `packages/server/public/boot-splash.css`
  - 启动覆盖层、字标、环形、浅色/深色、响应式、reduced-motion。
- `packages/server/public/boot-splash.js`
  - 暴露 `window.EABBoot`：
    - `maybeStart()`
    - `phase(text, progress)`
    - `ready()`
    - `fail(message)`
    - `cancel()`

不新增后端接口，不改登录接口，不改数据库。

### 6.2 页面接入

#### 管理端登录页 `admin-gate.html`

- 登录成功、`location.replace` 之前写入 `sessionStorage['eab.boot.next'] = 'admin'`。
- 保留现有 `POST /api/console/login` 与跳转地址，不加动画层，避免两个页面各播一次。

#### 管理端首屏 `index.html`

- `<head>` 引入 `boot-splash.css` 与 `boot-splash.js`。
- `<body>` 开头放静态启动层标记，保证首屏解析时就能覆盖，不等 JS 注入。
- 首屏脚本 `app.js` 在真实阶段调用 `EABBoot.phase()`：
  - 进入 `boot()`：`正在校验管理会话…`；
  - `/api/health` 完成：`正在加载控制台配置…`；
  - `loadCompanies()` 完成：`正在准备控制台…`；
  - `refresh()` 完成、或空库 `renderFirstCompany()` 完成：`EABBoot.ready()`。
- 失败路径：
  - `loadCompanies()` 抛错：先 `ready()` 再 `renderDenied()`；
  - 其他可捕获错误：`fail('控制台加载失败')` 后显示页面错误态；
  - 未登录被服务端重定向回登录页时，页面不会进入 boot，覆盖层不会残留。

#### 员工端 `chat.html` + `chat.js`

- `chat.html` 引入启动层与脚本；静态启动层放在 `<body>` 开头。
- 密码登录成功、`location.href` 之前写入 `sessionStorage['eab.boot.next'] = 'chat'`。
- 钉钉扫码登录成功、`location.href` 之前同样写入。
- `chat.js` 在真实阶段调用：
  - `boot()` 开始：`正在验证登录状态…`；
  - `/api/auth/me` 成功：`正在加载你的工作台…`；
  - `/api/me` 成功：`正在恢复会话…`；
  - `openSession()` / `newSession()` 与 `loadWorkspaceFiles()` 完成：`EABBoot.ready()`。
- 未登录、`?login=1`、会话失效：在 `showLogin()` 之前 `EABBoot.cancel()`。
- 无对话/无模型权限：在 `renderDenied()` 之前 `EABBoot.ready()`，让用户看到权限说明，而不是卡在启动层。
- `boot()` 最外层加兜底，任何未捕获异常都先 `ready()` 再展示错误页。

### 6.3 为什么用静态标记而不是 JS 动态注入

- 启动画面必须在页面第一次绘制之前就盖住首屏，否则会先闪一下空的工作台。
- 静态标记 + 同步脚本可以在 `<body>` 开头立刻显示，不依赖 DOMContentLoaded。
- 覆盖层默认 `hidden`，未命中一次性标记时零成本。

### 6.4 样式与主题

- 复用现有 `theme.js` 在 `<head>` 提前写入的 `html[data-theme]`。
- `boot-splash.css` 只读取现有 `--bg`、`--text`、`--brand` 等变量，不新造一套主题。
- 环形用 CSS `conic-gradient` + mask，不依赖 canvas/WebGL。
- 只动画 `opacity` 与 `transform`，不触发布局；`will-change` 只在覆盖层存在时使用。

### 6.5 S 电影片头版追加设计

#### 片源与规格

放在 `packages/server/public/boot/`：

- `eab-boot-chat-1080.mp4`：员工端主片，5–6s，H.264，`faststart`，目标 2.5–4 MB；
- `eab-boot-chat-720.mp4`：员工端移动/弱网降级，目标 1.2–2 MB；
- `eab-boot-admin.mp4`：管理端短片，3–4s，目标 1.2–2 MB；
- `eab-boot-chat-poster.jpg` / `eab-boot-admin-poster.jpg`：视频首帧，避免黑屏；
- 所有 MP4 必须把 `moov` 放到文件头（`ffmpeg -movflags +faststart`），首帧解码前就能开始播放。

#### EAB 品牌短片脚本（员工端 5–6s）

1. **0.0–1.0s**：近黑底，一条薄荷色细光从左上进入，勾出 EAB 方标的四条边；只听见很轻的低频环境声。
2. **1.0–2.2s**：四条边断开成四块几何，向中心聚合成方标；背景出现极淡的网格和颗粒，镜头缓慢推近。
3. **2.2–3.4s**：方标中心亮起，推入内部，浮出 `EAB` 字标和一行小字“企业智能体基座”；光线扫过一次。
4. **3.4–4.8s**：网格散开，画面从深绿过渡到工作台主题底色；字标定格。
5. **4.8–5.6s**：整体轻微后撤，片尾交叉溶解进工作台首屏。

管理端 3–4s 版本：去掉人物/情绪镜头，只保留“光带勾边 → 方标聚合 → 控制网格展开 → 管理控制台标题”，不改声音默认值。

> 不建议用同一支 6 秒片子硬套后台。后台是高频入口，太长会烦；员工端是“进入工作状态”的仪式，可以更有情绪。

#### 播放与状态机

- 启动层先显示 poster 首帧，视频 `canplay` 后静音自动播放；已被浏览器拒绝时显示“点击播放”，不显示黑屏。
- 音频默认关闭。右下角一个“声音”按钮，用户点击后 `video.muted = false`；不自动大声播放。
- 视频结束或用户点击“跳过”后，覆盖层 400ms 交叉淡出，露出已经完成布局的应用首屏。
- 如果应用还没就绪：视频播完后保持最后一帧，显示 CSS 状态；`EABBoot.ready()` 到达后再淡出。
- 如果应用先就绪：最多等到片长上限（员工端 6.5s、管理端 4.5s），到点强制淡出，不把用户困在片头。
- `prefers-reduced-motion: reduce`：不播放视频，直接显示 poster + 静态字标 + 状态，不请求视频资源。
- 视频 `error` / 解码失败 / 加载超时：500ms 内降级到 A+ 代码版，不显示黑屏。
- 触发规则沿用第 5 节：登录后播完整片头；同标签页刷新播轻启动代码动画；新标签页冷启动按配置播完整片头。

#### 媒体路由

- 新增只读路由 `GET /boot/<filename>`，不要复用登录接口。
- 必须支持 `Range` 请求：响应 `206 Partial Content`、`Accept-Ranges: bytes`、正确的 `Content-Range` 和 `Content-Type: video/mp4`；不支持 Range 时浏览器可能拒绝播放。
- 静态资源加内容哈希版本号，`Cache-Control: public, max-age=31536000, immutable`；换片时换文件名，避免缓存旧片。
- 不改 `POST /api/console/login`、`POST /api/auth/login`、钉钉回调、权限判断。
- 如果是 Express 静态目录且已支持 Range，可先验证再决定是否新增路由；不要默认它一定支持。

#### 前端组件追加

在 `boot-splash.js` 基础上增加 `EABFilm` 薄层，或直接扩展现有 `EABBoot`：

- `mount({ surface, video, poster, maxDuration, allowSound })`
- `ready()`：应用首屏就绪信号，沿用现有 `app.js` / `chat.js` 的 hook；
- `skip()`：淡出并销毁视频；
- `toggleSound()`：只允许用户手势触发；
- `fallback()`：切到 A+ 代码版；
- `dispose()`：清空 `src`、暂停、移除节点，避免后台继续解码。

视频节点建议：`playsinline muted autoplay preload="auto" poster="..."`，不显示原生 controls，不进入画中画。

#### 体积与网络

- 员工端首屏视频控制在 4 MB 以内；移动端用 720p 源。
- 内网 8787/8788 可直接预加载；外网部署时先看首帧 poster，不要为了片头把登录后的首屏拖慢。
- 不建议 4K、不建议透明 WebM/HEVC 作为唯一源；Chrome/Edge 优先 H.264 MP4。

### 7.3 S 电影片头专项验收

1. 视频通过 `Range` 请求返回 206，响应头 `Accept-Ranges: bytes`、`Content-Type: video/mp4` 正确。
2. 首次进入先显示 poster 首帧，不出现黑屏；视频 `canplay` 后静音自动播放。
3. 静音自动播放被拦截时显示“点击播放”，点击后正常播放。
4. 默认无声；点击“声音”后才出声，不自动大声播放。

6. 视频 404 / 解码失败 / 超时，500ms 内降级到 A+ 代码版。
7. `prefers-reduced-motion` 下不请求、不播放视频，只显示 poster 和静态字标。
8. 同一标签页刷新不重播完整片头，改为轻启动；新标签页/重新登录按配置播放完整片头；不叠加两个覆盖层。
9. 手机 375×812、桌面 1440×900 下 `object-fit: cover` 不出现关键文字被裁；员工端 720p 源生效。
10. 播放结束后视频节点被移除或 `src` 被清空，后台无残留解码和网络请求。

## 11. 后台配置启动动画

结论：**可以支持，而且应该做成配置中心，而不是写死在前端。**

### 11.1 配置层级

建议两级，避免“每家公司各改一份代码”：

| 层级 | 存放位置 | 作用 |
|---|---|---|
| 全局默认 | `.eab-dev/console-settings.json` 的 `bootAnimation` | 管理端 `/admin` 使用；员工端没有公司覆盖时的默认 |
| 公司覆盖 | `companies.settings_json.boot` | `/chat` 按当前公司读取；只合并 `boot` 一个 key，不覆盖助手等其它公司配置 |

这样：管理端保持统一品牌；员工端允许每家公司换片源、文案、声音和播放频率。

### 11.2 可配置项

| 配置项 | 取值 | 说明 |
|---|---|---|
| `enabled` | 开 / 关 | 总开关；关闭后直接进入首屏 |
| `surface.admin.mode` | `off` / `code` / `film` | 管理端用代码版或电影版 |
| `surface.chat.mode` | `off` / `code` / `film` | 员工端用代码版或电影版 |
| `assetId` | 媒体库 ID | 只允许选已上传并校验过的 MP4，不允许填任意 URL |
| `durationMax` | 0.8–8 秒 | 片长上限；到点必须淡出，不能把用户锁住 |
| `allowSound` | 开 / 关 | 是否显示声音按钮；默认仍然静音起播 |
| `allowSkip` | 开 / 关 | 是否显示“跳过”；建议默认开 |
| `playOn` | `login` / `new-session` / `always` | 登录后播 / 每个新标签页播 / 每次都播 |
| `copy.title` | 文本 | 启动层主标题，默认 `EAB` |
| `copy.subtitle` | 文本 | 副标题，默认“企业智能体基座” |
| `revision` | 整数 | 每次保存自增，用于客户端缓存失效 |

不建议开放“自定义 HTML / JS / 任意外链视频”。这会把启动层变成 XSS 和弱网黑屏入口。

### 11.3 接口与存储（已实现）

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/console/boot` | GET | 控制台读取全局配置、当前公司覆盖、媒体库列表 |
| `/api/console/boot` | PUT | 保存全局配置，写 `console-settings.json`，自增 `revision`，审计 `boot.global.save` |
| `/api/console/company/boot` | PUT | 只合并 `companies.settings_json.boot`；body 为 `{ useGlobal, chat }`，审计 `boot.company.save` |
| `/boot/config.js?surface=admin\|chat` | GET | 公开只读配置；按 surface 返回生效后的展示配置和 `revision`，不返回路径或内部字段 |
| `/boot/assets/:assetId` | GET | 只读媒体路由，支持 `Range` / `206`；非法 Range 返回 `416` + `Content-Range: bytes */总长` |
| `/api/console/boot/assets` | POST | 上传 MP4，raw `video/mp4`，文件名走 `x-file-name`，审计 `boot.asset.upload` |
| `/api/console/boot/assets/:assetId` | DELETE | 删除片源；正被全局或公司配置引用时返回 `409`，审计 `boot.asset.delete` |

存储位置：

- 全局：`.eab-dev/console-settings.json` 的 `bootAnimation`。
- 公司覆盖：`companies.settings_json.boot`，只合并 `boot` 一个 key。
- 片源：数据目录 `boot-assets/<assetId>.mp4` + `<assetId>.json`，媒体 ID 为 `boot-<sha256 前 24 位>`，不写进仓库 `public/`。
- 保存后不立即打断当前会话；页面显示“刷新两端后生效”。

现有 `ConsoleSettings` 已增加 `bootAnimation`；`writeConsoleSettings` 对 `bootAnimation` 做显式合并，不整段覆盖。

### 11.4 管理后台界面（已实现）

实际入口：`/admin?company=c1` →「连接与平台」→「系统」→ 页内标签「启动动画」。

- 面板标题「登录后启动动画」，右上显示「已启用 · rev N」。
- 「全局启用」总开关：关闭后两端都不播，公司覆盖也不能单独打开。
- 左右两张卡：管理控制台、员工工作台；各有模式（关闭 / 代码高定 / 电影片头）、片源、时长上限、播放规则、标题、副标题、声音开关、跳过开关。
- 「使用全局默认」开关：公司覆盖开启后才启用员工端的公司字段；管理端固定使用全局。
- 按钮：保存全局配置 / 保存为跟随全局 / 保存公司覆盖 / 上传 MP4 片源。
- 预览：管理端与员工端各一个真实预览按钮，不写入 `seen` 标记；预览会强制播放电影片头，不受当前系统 reduced-motion 影响。
- 媒体库：列出 ID、文件名、时长、体积；每行「删除」需连点两次确认，被引用时后端返回 409。
- 保存/上传/删除的成功或失败反馈都在面板重绘后重新写入，不会被 `loadSys()` 清空。

### 11.5 媒体上传与安全

- 只接受 `video/mp4`，建议单文件 ≤ 8 MB；员工端再自动选择 720p 小片。
- 服务端校验文件头、MIME、大小；时长优先用 `ffprobe`，没有 ffprobe 时解析 MP4 `mvhd`，不能只信前端传的 duration。
- 文件名用服务端生成的 ID，原始文件名只做展示；禁止路径穿越。
- 媒体目录跟数据目录走，进备份；只保留当前和上一版，旧片可回滚。
- 文案做纯文本转义，长度限制；禁止 HTML。
- 上传、删除、发布都需要控制台会话；公开只读路由只吐展示配置和媒体字节。

### 11.6 失败与降级（已实现）

- 配置读取失败 / 超时：使用内置默认配置，不阻塞首屏。
- `film` 片源 404、解码失败、Range 不支持、自动播放被拒：显示“点击播放”或回退 `code`，不黑屏。
- 配置里 `enabled=false`：不播启动层，直接进入首屏。
- 公司覆盖损坏：回退全局默认，不静默删除公司配置。
- `prefers-reduced-motion`：真实登录不播放视频，回退静止代码版；后台“预览”按钮例外，用于检查电影片头本身。
- 启动层脚本或样式缺失：必须保证 `boot-splash.css` / `boot-splash.js` 有静态路由，否则页面会只剩裸文字。该问题已在真实浏览器中复现并修复。

### 11.7 实施顺序（已完成）

### 修复记录（2026-11-16）

登录门写入 `sessionStorage['eab.boot.next']` 后，启动脚本读取该标记时调用了当时不存在的 `safeRemove()`，导致 `bootIntent()` 抛错、脚本中断，启动层永远停在“正在加载控制台配置…”。已修复：

- 补齐 `safeRemove()`，与 `safeGet/safeSet` 一样对 `sessionStorage` 不可用做兜底。
- 启动脚本初始化外层加 `try/catch`：自身异常时直接隐藏覆盖层并进入页面，不再遮住后台。
- `app.js` 的 `boot()` 增加 `.catch()`，控制台初始化异常时调用 `EABBoot.fail()`，避免启动层无限停留。
- 已真实回归：管理端普通刷新、登录跳转标记、员工端登录跳转标记三条路径均正常退场，启动层 `hidden=true`、`aria-hidden=true`，且 `eab.boot.next` 被消费。

真实验收：

- 管理端 `/admin?company=c1`：刷新时约 0.1s 即显示深色启动层，状态“正在恢复控制台…”→“正在进入控制台…”→“即将进入”，约 0.76s 退场；底层恢复，无滚动条。
- 员工端 `/chat?company=c1`：刷新时约 0.1s 即显示启动层，状态“正在恢复会话…”→“正在进入工作台…”→“即将进入”，约 0.71s 退场；登录门不长时间遮挡。
- 首帧兜底：`html`/启动层内联深绿背景 + 启动层 DOM 提前到配置脚本之前；`boot/config.js`、`boot-splash.js`、`app.js`/`chat.js` 改为 `defer`，配置请求不再阻塞首帧。
- 轻启动规则：最短 480ms，应用 `ready()` 后 0.34s 淡出；650ms/2s 两档慢加载文案；2.6s 强制退场；普通刷新不请求 MP4、不播放声音。
- 后台标签页：`requestAnimationFrame` 不触发时改用计时器退场，避免启动层无限遮挡。
- `node --check boot-splash.js`、`pnpm typecheck`、全量 `pnpm test`（124 文件 / 708 用例）通过。
