# EAB v2026.11.23.01 发布说明

发布日期：2026-11-23
版本类型：补丁版本（修「一键更新」失败后服务起不来）
发布基线：`main`

## 版本概述

`v2026.11.23.01` 是 `v2026.11.23` 的补丁版本，只处理控制台「系统 › 系统更新」里**一键更新必现失败、失败后服务也起不来**的问题，不改业务功能、不改数据库迁移。

## 问题与根因

- 现象：从控制台点「一键更新」后，日志停在“依赖安装完成”（仅 0.5 秒），随后重启 45 秒健康检查超时，兜底重启仍超时，回滚之后服务依旧无响应，更新被判失败。
- 直接报错：前台启动时报 `ERR_MODULE_NOT_FOUND: Cannot find package '@deepseek-ai/cosmokit'`（`packages/server/node_modules/@deepseek-ai/cordis/lib/index.js`）。
- 根因：更新器备份代码用 `cpSync` 整目录拷贝，把 pnpm 的 junction 软链**解引用成了真实副本**；替换代码会删掉整个 `packages`（连带各包 `node_modules`），而 `pnpm install --frozen-lockfile` 常因根装配未变而跳过链接重建（曾见 384ms "Already up to date"）。回滚时先删目录再拷回备份，等于把软链结构彻底破坏，所以失败后也起不来。

## 修复内容

- `scripts/eab-update.mjs`：新增 `skipNodeModules(source)` 过滤器，`backupCode` 与 `restoreCode` 的 `cpSync` 都跳过路径段为 `node_modules` 的内容，备份不再解引用软链，体积也大幅缩小。
- `scripts/eab-update.mjs`：`runPnpm(root, { force })` 支持 `--force`；替换代码后，以及正常回滚、异常 catch 两条回滚路径，统一改为 `pnpm install --force --frozen-lockfile` 强制重建依赖链接（234 个包，约 24–32 秒）。
- `scripts/eab.mjs`：`login()` 改用 `res.headers.getSetCookie()` 按名字取 `eab_console_sid`。登录接口会先下发一条清除成员会话的 `Set-Cookie`、再下发控制台会话，旧代码只取第一条，导致 `eab doctor` 误报「控制台接口需登录」。

## 验证

- 本地执行 `node scripts/eab.mjs update 2026.11.23 --force` 全流程通过：备份代码与运行数据 → 替换 → `pnpm --force` → 重启 → 健康检查（`v2026.11.23 pid=19280 uptime=4s`），`last-update.json` 为 `"status":"succeeded","rolledBack":false`。
- 更新后 `node scripts/eab.mjs doctor` 七项全绿（服务、数据库、控制台凭据、密钥文件、插件目录、审计链 2654 条、备份 2 个快照），`/api/health`、`/chat`、`/admin` 均返回 200。
- `@deepseek-ai/cordis` 已恢复为 Junction 指向 `.pnpm` 虚拟店，软链结构正常。
- 临时脚本验证 `filter` 行为：拷贝 `packages/server` 到临时目录后 `node_modules` 不存在、`public/app.js` 存在。
