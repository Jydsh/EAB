# EAB v2026.11.23.04 发布说明

发布日期：2026-11-23
版本类型：补丁版本（数据类回答必须真取数，且对所有工具生效）
发布基线：`main`

## 版本概述

`v2026.11.23.04` 是 `v2026.11.23.03` 的补丁版本，专治“没查就答、拿别人的数据凑答案”：模型在长对话里跳过工具，直接复用上一轮的人名和数字；或者只调一次零参数的接口清单，就照着清单编数据。

## 问题与根因

- 现象一：问「邓骏的本月加班数据」，整轮 `toolCalls` 为空，答案直接是上一轮「魏竣豪 17 条 / 213.27 小时」换了个人名。
- 现象二：问某个员工，返回的却是整组 105 条 / 864.92 小时——姓名筛选没生效，整组合计被当成个人数据。
- 现象三：明细表里同一行被复制几十遍、出现“平均每天 28.8 小时”这类不可能结论；批次结果被截断后模型没有 `batch_read` 就写表。
- 根因一：交付前门禁判断“有没有业务工具”时只取公司实例插件；本地 `dsh-cy-api` 是个人安装，清单为空，门禁静默失效。
- 根因二：门禁只认 `plugin:` 前缀的工具，知识库、数据库、文件读取这些同样能取数的工具不在管辖范围。
- 根因三：历史对话记忆与会话摘要被当作可引用的事实，上一轮的数字因而可以顺手复用。

## 修复内容

### 取数门禁对全部工具生效

- 工具识别改为按能力判断：插件、知识库检索、数据库查询、云空间/文件读取、MCP、时钟都算取数工具；用黑名单排除元工具与写操作（`tool_search`、`math.eval`、`ask_user`、`agent.*`、`memory.*`、`cron`、`skill`、写文件、发消息、上传等）。
- 一次调用要算“真取到数”，必须同时满足：状态成功、带参数（问时间时钟除外）、返回内容非空。零参数的接口清单、带参数但只是 `math.eval` 算数，都不算取到数。
- 插件工具清单改为“公司实例 + 个人安装”并集，并用 `toolId` 前缀兜底识别，避免本地个人安装导致清单为空。
- 门禁连续拦截两次后放行，避免对话卡死；没有任何取数工具可用时不做无意义的强制调用。

### 对话记忆与摘要降级为线索

- 取数轮不再注入历史对话记忆片段，避免把上一轮答案里的数字当成本轮结果。
- 长期背景记忆与会话摘要保留用于理解意图，但明确标注“其中的数字、名单、状态已过时，只能当线索”。
- 系统提示新增【实时数据硬规则｜对所有工具一视同仁】：记忆、摘要、历史对话、上一轮工具结果、模型常识都不是准确数据；工具结果对不上就改参重查；全都查不到就如实说查不到。

### 参数与口径校验

- 插件调用按 schema 校验必填参数，缺 `Username`/时间范围这类必填项直接抛校验错误回给模型补齐，避免空参查询拿到全公司/全组数据。
- 批次结果落盘后不再注入被截断的 JSON 前缀，改为“表头一次 + 每行一行 TSV”的真实行预览，并写明“共 N 行，未列出的行必须 `batch_read`，一条都不许编造”。
- `rowStats` 增加身份字段分布标签；返回里出现多个姓名时在工具结果前注入硬警告：这批数据不是一个人，合计不能当作某个人的答案。

### 输出前复核锚点

- 每轮系统提示尾部重新锚定本轮用户原话，并列出六条复核项：不搬上一轮结论、要数据先取数、条件原样传参、已知接口直接调、返回后核对姓名与日期、查不到就说查不到。

## 数据库

本版无迁移，不改任何表结构。

## 验证

- 新增单测：门禁决策（插件/知识库/文件读取/时钟放行，零参数清单与算数工具不放行，连续两次后放行）、取数轮提示降级（不注入历史记忆、摘要标过时、非取数轮不受影响）、锚点与必填参数、批次 TSV 预览、`rowStats` 身份标签。
- `pnpm typecheck` 通过；全量 `pnpm test` 224 个文件 / 1363 个用例全部通过。
- 本地真实链路复核：问「邓骏的本月加班数据」，第一轮只调零参数接口清单被门禁拦下，第二轮带参查询返回 3 条 / 17.03 小时；问「公司差旅报销标准是多少」，`kb_search` 带关键词连查数次，未命中时如实回答查不到，没有用记忆补数字。
