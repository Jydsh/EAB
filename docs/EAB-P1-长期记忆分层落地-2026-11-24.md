# EAB 长期记忆分层落地（P1，2026-11-24）

对应设计：`EAB-P1-长期记忆分层设计-2026-11-24.md`。本轮把设计里的 A、B、C、D、E 五个方向做成可运行第一版，并补上 F 阶段的 100 条抽取基准、100 轮针事实召回探针和面板运行入口；核心目标是先修掉“聊到第 100 轮就忘了第 1 轮”的硬伤，同时让个人记忆像通用 Agent 一样自动生效，团队记忆仍保留管理员闸门。

## 2. 数据结构

迁移：`packages/storage/migrations/0102_memory_layers.sql`、`0103_memory_maintenance.sql`、`0104_memory_extraction_runs.sql`、`0105_memory_benchmark_runs.sql`。

`memories` 新增可空列：

- `subject / predicate / object_text / fact_key`
- `confidence / importance / sensitivity`
- `source_message_id / extraction_source`
- `valid_from / valid_to / last_access_at`
- `event_at / salience`
- `archived_at / cluster_key / merged_from / recall_count / last_recalled_at`

新增 `memory_maintenance_runs` 表，记录每次整理的开始时间、结束时间、合并组数、归档条数。维护表只保留运行摘要，不复制记忆正文。

新增 `memory_extraction_runs` 表，记录每轮自动抽取的渠道、模式、抽取/写入/生效/重复/冲突/敏感跳过数量和耗时，不保存用户原话。

新增 `memory_benchmark_runs` 表，记录基准版本、总用例数、通过数、应抽取/命中/漏写、应忽略/误写、敏感用例/泄漏、命中率/漏写率/误写率/通过率、100 轮召回是否命中与排名、耗时和失败用例编号。失败编号只保存 `fear-06` 这类 id，不保存合成用例原句。

新增索引：

- `idx_memories_fact_key (company_id, scope_type, scope_id, fact_key, valid_to)`
- `idx_memories_validity (company_id, deleted_at, valid_to, confirmed)`
- `idx_memories_archive (company_id, scope_type, scope_id, memory_type, archived_at)`
- `idx_memories_cluster (company_id, cluster_key, archived_at)`
- `idx_memory_maintenance_runs (company_id, started_at DESC)`
- `idx_memory_extraction_runs_user (company_id, user_id, created_at DESC)`
- `idx_memory_extraction_runs_channel (company_id, channel, created_at DESC)`

旧数据不重建、不回填；读取时仍然回退到 `content`。这样升级可以直接跑，不需要停机迁移历史文本。

## 3. 召回与提示装配

1. `routes/chat.ts` 的长期记忆候选 SQL 去掉了 `ORDER BY created_at DESC LIMIT 20`，改为有效记忆全量候选（安全上限 2000 条），并过滤 `valid_to`。
2. 已有 `fact_key` 的结构化事实不再进入普通召回池，由画像卡统一承载，避免同一事实在提示里出现两遍。
3. 召回打分改为固定权重：相关性 0.6、新近度 0.2、重要性 0.2；`preference / fact / decision` 不随时间衰减，`episode` 按半衰期衰减。
4. 对内容高度相近的非情景记忆做轻量去重；同一句话在不同时间发生的情景保留为不同条目。
5. 系统提示的 `memory` 段现在按顺序装配：
   - 结构化画像卡（最多 12 条事实、约 900 字）；
   - 普通长期记忆（最多 4 条）；
   - 会话摘要；
   - 历史对话片段；
   - 引用对话；
   - 知识库片段。
6. 顺手修正了 Prompt Compiler 分段错位：附件块进入 `task` 段，长期记忆不再被误放进 `tools` 段，数据回合规则回到 `tools`。

画像卡取值规则：

- 只看 `confirmed=1`、未删除、未失效、`fact_key` 非空、`sensitivity != sensitive` 的事实；
- 同一 `fact_key` 同时出现在个人 / 部门 / 公司时，按“个人 > 部门 > 公司”取一条；
- 先按重要性和时间排序，再按字数上限截断。

## 4. 写入与维护语义

### 4.1 `memory.propose`

工具参数新增 `factKey / subject / predicate / object / confidence`。当 `memoryType=fact` 且给出 `factKey` 时：

- 同键同对象值：返回 duplicate，不再插入；
- 同键不同对象值：形成冲突，新记忆保持 `confirmed=0`，`conflict_with` 指向旧事实，等本人确认；
- 模型只给 `content`、没给结构化槽位时，会尝试从“我叫小张 / 我习惯…”这类高置信句式补键；
- 个人范围、高置信、不冲突的偏好/事实/决策直接 `confirmed=1` 生效，工具返回 `自动生效` 提示；团队范围仍走管理员审核。

### 4.2 手工新增

`POST /api/memories` 选择 `memoryType=fact` 时，同样会从内容推导结构化槽位。用户手工写“我叫小张”，默认直接进入画像卡；只有与旧记忆冲突时才停在待确认区。

### 4.3 确认

确认结构化事实时：

- 同公司、同范围、同 `fact_key` 的已确认旧事实写 `valid_to=now`；
- 旧事实不软删除，保留审计和历史；
- 新事实写 `valid_from`，清空 `valid_to`；
- 返回 `expiredFactIds`，前端和审计能看到替换了哪些旧事实。

非结构化冲突仍沿用旧语义：确认新记忆时软删除旧记忆。

### 4.4 删除

`DELETE /api/memories/:id` 现在同时：

- 写 `deleted_at`；
- 写 `valid_to`；
- 清空 `embedding / embedding_model`。

这样旧向量不会在删除后继续参与召回。

## 5. 自动抽取

文件：`packages/server/src/memory-extractor.ts`。

模式由环境变量控制：

| 值 | 行为 |
| --- | --- |
| `off` | 完全关闭自动抽取 |
| `rules` | 默认；只抽第一人称高置信事实和明确偏好，不额外调用模型 |
| `llm` | 规则抽取 + 一次模型 JSON 抽取，模型失败自动退回规则结果 |

默认是 `rules`，原因是不增加每轮模型成本，同时能覆盖“我叫小张 / 我怕狗 / 我习惯… / 以后都用表格回复”这类典型场景。

自动生效由 `EAB_MEMORY_AUTO_CONFIRM` 控制，默认 `on`：

| 条件 | 行为 |
| --- | --- |
| 个人 `user` 范围 + 事实置信度 ≥ 0.85 | 直接生效 |
| 个人 `user` 范围 + 偏好/决策置信度 ≥ 0.8 | 直接生效 |
| 情景、低置信、与旧记忆冲突 | 保持待确认 |
| `dept / company` 范围 | 永不自动生效，必须管理员确认 |
| 设 `EAB_MEMORY_AUTO_CONFIRM=off` | 退回全影子模式，所有候选都要手工确认 |

安全约束：

- 自动候选只写 `scope_type='user'`，不自动写 `dept / company` 范围；
- 含邮箱、手机号、身份证、银行卡、密码、密钥、验证码等内容的整轮文本直接跳过；
- 同一事实重复出现只记一次；
- 同键不同值只落冲突行，不覆盖已确认事实；
- 抽取在回复落库后异步执行，失败只写服务日志，不影响本轮回答。

## 6.1 召回解释

每轮回答完成后，在回答上方显示 `长期记忆 · 想起了 N 条`，默认折叠。展开后逐条显示：

- 记忆类型与范围：偏好/事实/决策/情景，个人/部门/公司；
- 综合分，例如 `0.90`；
- 命中原因：`词面命中 6 个词 · 公司 · 重要性 0.50`；只有语义相似度 ≥ 0.70 时才会额外显示 `语义相近 x.xx`。

这些原因同时写入消息 `meta.longTermMemoryRecall`，刷新页面后仍可回看；不进入模型提示。

## 8. D 阶段维护细节

文件：`packages/server/src/memory-maintenance.ts`。

### 8.1 情景聚类

- 只看未归档、已确认的 `episode`；按 `scope_type + scope_id` 分组，个人/部门/公司各管各的，不跨范围合并；
- 最近 60 天内、两两相隔不超过 7 天、内容相似度 ≥ 0.55 的记录归为一组；
- 每组至少 2 条才合并；
- 合并生成一条 `extraction_source='consolidated'` 的合集，正文由各原始情景去重后拼接，上限 500 字；
- 原始记录写 `archived_at` 和 `cluster_key='ep_<sha1 前16位>'`，不再参与召回，但保留审计；
- 合集写入 `merged_from` JSON 数组，前端显示“合并 N 条”。

### 8.2 旧情景归档

- 超过 120 天且 `recall_count=0` 的情景直接写 `archived_at`；
- 被归档记录仍能通过“已归档”页签查看，不物理删除。

### 8.3 调度与审计

- 后台 worker 启动后延迟 1 分钟首跑，之后每 6 小时检查一次；
- 20 小时内不重复自动运行，除非管理员调用 `POST /api/memories/maintenance/run`；
- 每次运行写 `memory_maintenance_runs`，并在审计日志记录 `memory.maintenance`。

- 每轮抽取写一条 `memory_extraction_runs`，只存计数和渠道，不存用户原话；
- `GET /api/memories/stats` 新增 `extraction`：近 7 天轮次、抽取数、写入数、生效数、待确认、冲突、重复、敏感跳过、空结果轮次、生效率、重复率、冲突率，以及各渠道轮次；
- “我的记忆”面板在整理记录上方显示一行抽取质量，例如 `近 7 天自动记忆：12 轮，生效 5 条（83.3%），待确认 1 条，冲突 0 条，重复 2 条；网页 10 轮、钉钉 2 轮`；
- 统计只按当前登录成员自己的运行记录计算，不混入其他人的个人抽取数据。

## 10. F 阶段：抽取基准与 100 轮召回探针

### 10.1 固定数据集

- 版本 `2026-11-24.1`，共 100 条合成用例：60 条应抽取、30 条应忽略、10 条敏感凭证；
- 应抽取用例覆盖偏好、事实、决策、习惯、恐惧和关系等类型；应忽略用例覆盖寒暄、一次性任务、第三人称描述和无信息量句子；敏感用例覆盖密码、密钥、身份证、银行卡和验证码；
- 评估器是纯函数，只判断该不该抽、类型是否正确、是否被敏感过滤拦住，不调用真实写入链路，也不污染真实 `memories`；
- 结果只落 `memory_benchmark_runs`，保存计数和失败用例编号，不保存合成原句。

### 10.2 指标口径

- 命中：应抽取用例产出了候选，且记忆类型正确；
- 漏写：应抽取用例没有产出候选，或类型不符；
- 误写：应忽略用例产出了候选；
- 敏感泄漏：敏感用例没有被拦截；
- 通过率 = 正确分类的用例数 / 100；漏写率分母是应抽取数，误写率分母是应忽略数。

### 10.3 100 轮召回探针

- 第 1 轮写入针事实“我的工号是 EAB-9527。”；
- 中间积累 99 条项目噪声，来自 33 个主题 × 3 种结尾；
- 第 100 轮以“我的工号是多少？”查询，用 `selectRelevantLongTermMemoriesDetailed`、`limit=4` 判断针事实是否仍在窗口内，并记录排名；
- 这验证的是存储、索引和选择策略，不是实际 100 轮模型对话；真实端到端评测仍留在未完成清单。

### 10.4 接口与面板

- `POST /api/memories/benchmark/run` 需要 `memory:write`，运行后写审计 `memory.benchmark`，资源类型 `memory_benchmark`；
- `GET /api/memories/stats` 返回 `benchmark.dataset` 和 `benchmark.lastRun`；没有运行时 `lastRun=null`；
- 面板“规则基线”块显示最近一次摘要与“运行评测”按钮；运行中按钮变为“评测中…”，成功后刷新面板，失败只提示横幅，不覆盖上次结果。

### 10.5 真实基线

- 100 条通过 92 条，通过率 92%；
- 应抽取命中 56，漏写 4，命中率 93.3%，漏写率 6.7%；
- 应忽略误写 4，误写率 13.3%；
- 敏感泄漏 0；
- 100 轮针事实召回命中，排名第 1。
