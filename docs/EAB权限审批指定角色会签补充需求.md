# EAB 权限审批「指定角色」会签补充需求

> 状态：需求口径已确认，待实现
> 更新时间：2026-11-21
> 关联文档：[EAB权限审批流程设计器方案](./EAB权限审批流程设计器方案.md)

## 一、背景

改造前，流程设计器的审批节点只支持「部门负责人链 / 指定成员 / 申请人直属上级 / 公司管理员」四种来源；「会签」也只按节点顺序拆成多个串行步骤，不是同一节点多人并行审批。

本次补充「指定角色」审批人来源，并明确角色审批的会签语义：**选中角色后，该角色内符合条件的成员全部进入同一个审批节点；每个人同时收到待办，不排序；全部同意后流程才进入下一节点。**

## 二、权威口径

### 2.1 角色选择

1. 审批节点增加第五种来源：`指定角色`，数据字段为 `source='role'`、`roleCode`、`roleName`。
2. 只允许选择角色自身拥有 `approval:decide` 权限的角色，避免选中后角色成员无法审批。
3. 角色选择弹窗展示角色名称、成员数量；成员数为 0 的角色不可保存。
4. 指定角色节点的审批方式固定为「会签」，不提供「或签 / 依次审批」，避免与“全部成员都要审批”的语义冲突。

### 2.2 成员范围

角色节点的审批集合在**提交申请时快照**：

- 角色内当前有效的全部成员；
- 排除申请人本人，申请人不能审批自己的申请；
- 排除已停用、已删除、非本公司的成员；
- 每个成员必须实际具备 `approval:decide`；提交时若发现角色成员缺少该权限，拒绝建单并返回缺失成员，不静默跳过。

后续角色成员增加或减少，不影响已创建申请；新申请按提交时的新成员集合生成。

### 2.3 审批方式

1. 同一角色节点的所有审批人使用同一个 `step_no`，各自一条审批步骤记录，全部为 `active`。
2. 不设置先后顺序，所有人在申请提交后同时进入待办，并同时投递钉钉审批卡。
3. 任意一人同意，只将本人的步骤改为 `approved`；申请仍停留在当前节点，等待其余成员。
4. 全部成员同意后，当前节点才算完成，流程进入下一节点；若无下一节点，则写入个人权限授权并结束。
5. 任意一人拒绝，整张申请立即拒绝；当前节点其他未处理成员及后续节点全部置为 `skipped`。
6. 已同意的成员不因后续他人拒绝而回退状态，保留真实审批记录。
7. 重复点击、重复卡片回调只产生一条决策，不重复推进流程。

### 2.4 空角色与异常

- 角色内没有可审批成员：提交时拒绝，提示“角色没有可审批成员”。
- 角色成员缺少 `approval:decide`：提交时拒绝，提示具体成员数量，不生成残缺会签。
- 某个成员未绑定钉钉：不影响建单，网页待办仍可审批；钉钉卡片标记投递失败并按原机制重试。

### 2.5 控制台兜底

- 控制台审批记录展示同一节点的多名审批人及“已通过 N / 共 M 人”。
- 平台管理员在控制台点击“同意”时，视为一次完成当前会签节点：当前节点全部待审批成员记为同意并推进下一节点。
- 普通审批人仍只能处理自己那一条，不能替其他成员同意。

## 三、界面要求

### 3.1 流程设计器

- 「审批人来源」下拉增加「指定角色」。
- 选中指定角色后：
  - 显示已选角色名称和成员数量；
  - 显示“全部成员会签，申请人本人除外”的说明；
  - 提供「选择角色 / 重新选择角色」；
  - 审批方式显示为只读「会签」。
- 画布节点摘要显示“指定角色 · 角色名 · 全体成员会签 · 时限”。

### 3.2 审批记录

- 当前节点显示为“第 N 步 · 张三、李四（1/2 已批）”，不再只显示第一个审批人。
- 详情时间线把同一 `step_no` 的多人合并为一个会签节点，展示每个人的状态。
- 进度条按真实节点总数计算，不再固定按 3 级计算。

## 四、数据与兼容

1. 新增迁移，允许同一申请单的同一 `step_no` 存在多名审批人，唯一键改为 `(request_id, step_no, approver_user_id)`。
2. `total_steps` 表示审批节点数，不表示审批人数；角色会签节点无论多少人都只占 1 个节点。
3. 已有申请单、单人会签、或签和依次审批保持原有行为。
4. 现有内置示例流程不参与运行时匹配，不受本次改动影响。

## 五、验收用例

1. 角色有 3 名可审批成员：建单后 3 人同时出现在待办，`total_steps=1`，3 条步骤同为第 1 步且全部 `active`。
2. 第 1 人同意：申请仍为 `pending`，当前步骤仍为 1，第 2、3 人仍可审批。
3. 第 2 人拒绝：申请立即 `rejected`，第 3 人置为 `skipped`，不写任何授权。
4. 3 人全部同意：申请 `approved`，只写一次个人权限授权，不重复写。
5. 同一人重复同意：只落一条决策，不推进两次。
6. 角色成员包含申请人本人：申请人不进入审批集合。
7. 角色成员缺少 `approval:decide`：建单失败，提示缺失成员。
8. 指定角色节点在流程设计器保存、发布、刷新后仍保留 `roleCode`，运行时能正确展开成员。
9. 控制台点击一次同意可完成当前会签节点，并显示“已通过 N / 共 M 人”。

## 六、本轮不做

- 或签节点的多人并发展开；或签仍只取第一位审批人。
- 转交、加签、超时自动升级。
- 角色成员在审批过程中动态加入当前申请。
- 角色范围本身变更后的在途申请重算。
