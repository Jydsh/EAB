# EAB P1 · AGT-14 个人偏好记忆工具

> 版本：`2026.11.23.04`（本轮未升级版本号）
> 日期：2026-11-24
> 审计来源：`docs/EAB-Agent框架对照审计与能力建设需求-2026-11-23.md` §7.2
> 验收口径：模型在对话中能主动识别“记住我的偏好”，把个人偏好写成当前用户待确认记忆；用户本人在“我的记忆”确认后才生效；不共享给团队；与旧偏好冲突时不静默覆盖。

## 1. 本轮解决的问题

AGT-13 完成后，记忆已有四类、冲突待确认和混合召回，但 `memory.propose` 只有一条路径：写公司级团队学习，等管理员审核。

个人偏好仍只能由用户手动新增。用户在对话中说“记住我的格式偏好”“以后给我这样回复”时，模型不能主动落成个人记忆，也不会提醒用户去确认。

AGT-14 把同一个工具扩展成**双范围入口**：

- `scopeType=user`：写当前成员的个人记忆，本人确认后生效；
- `scopeType=company`：保持原团队学习路径，管理员审核后生效。

## 2. 工具合同

工具 id 不变，仍为 `memory.propose`，避免已有提示词和调用记录失效。

展示名从“提交团队学习”改为“记住偏好或团队规则”。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `content` | string，必填 | 提炼后的可复用内容，最多 1000 字 |
| `scopeType` | `user` / `company` | 个人记忆或团队规则；缺省仍是 `company`，兼容旧调用 |
| `memoryType` | `preference` / `fact` / `decision` / `episode` | 个人默认 `preference`，团队默认 `decision` |

description 明确两类触发语：

- “记住我的偏好 / 以后给我这样回复 / 我习惯用这个格式” → `user`；
- “让团队都按这个规则 / 把这条经验分享给大家” → `company`。

工具描述同时要求只提交提炼后的规则，不提交原始聊天、密码、手机号、身份证号、客户隐私或一次性任务内容。

`toolHints['memory.propose']` 增加个人侧触发词：`个人偏好`、`我的偏好`、`记住我的`、`我的格式`、`以后给我`、`我习惯`、`preference`、`personal`。

## 3. 写入与确认规则

### 3.1 个人偏好

当 `scopeType=user`：

- `scope_type='user'`；
- `scope_id=actor.person.id`；
- `user_id=actor.person.id`；
- `confirmed=0`；
- 不写公司范围，不进入团队上下文。

返回：

```json
{
  "scopeType": "user",
  "memoryType": "preference",
  "confirmed": false,
  "status": "pending",
  "conflictWith": null
}
```

提示语明确“待你在‘我的记忆’确认后生效；不会自动共享给团队”。

### 3.2 团队规则

当 `scopeType=company`：

- `scope_type='company'`；
- `scope_id=companyId`；
- `user_id=actor.person.id`；
- `confirmed=0`；
- 仍需 `memory:admin` 审核。

原团队候选行为不变。

### 3.3 重复与冲突

查重和查冲突仍调用 `findMemoryDuplicateOrConflict()`，比较范围严格限定为**同公司、同 scopeType、同 scopeId、同 memoryType**。

- 个人重复：返回已有记忆 id，`duplicate: true`，不插新行；
- 个人冲突：新记忆落 `confirmed=0`，`conflict_with=旧个人记忆 id`，状态 `conflict`；
- 旧个人记忆保持 `confirmed=1, deleted_at=NULL`，不会被自动软删除；
- 用户在“我的记忆”确认替换后，才走 AGT-13 的事务：软删除旧记忆、新记忆生效。

个人提示语不再写死“偏好”，改为“个人记忆候选”和“旧记忆”，避免 `memoryType=fact/decision` 时文案误标。

### 3.4 权限与审计

- 工具本身仍要求 `SC.MEMORY_WRITE`；
- 个人记忆确认只允许本人；
- 公司/部门记忆确认或删除仍要求 `memory:admin`；
- 审计 `memory.propose` 的 detail 新增 `scopeType`，并保留 `memoryType`、长度、冲突 id。

## 4. 记忆管理界面

`public/chat.js` 的“我的记忆”弹层：

- 范围标签从原始 `user/company` 改为中文：`个人 / 部门 / 公司`；
- 说明改为“模型提议的个人偏好也会先出现在这里，需你本人确认”；
- 个人待确认记录显示 `待确认 · 偏好 · 个人`；
- 确认后变为 `已确认 · 偏好 · 个人`；
- 冲突仍显示“确认替换”，不会静默覆盖。

## 6. 当前边界

1. 个人偏好写入仍需要模型主动判断“这是长期偏好”而不是一次性指令；工具描述和触发词已覆盖常见表达，但边界表达仍可能漏判。
2. 个人偏好默认 `preference`；如果内容明显是事实（如工号、环境地址），模型可传 `memoryType=fact`，但仍需本人确认。
3. 冲突判定沿用 AGT-13 的字符相似度启发式（阈值 0.5），不是语义模型判定；不同表述但同义的冲突可能漏拦。
4. `scopeType` 缺省仍为 `company`，这是为兼容旧团队调用保留的行为；个人场景依赖模型按 description 选择 `user`。真实对话已验证模型会正确选择。
5. 个人记忆的确认入口目前在“我的记忆”弹层，没有在对话消息里加一键确认按钮；用户需要多点一步进入设置。
6. 版本号仍为 `2026.11.23.04`；是否升级、是否 commit/push 按用户要求另行确认。
