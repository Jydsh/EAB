# EAB P0：任务详情可观测页（AGT-07）

日期：2026-11-24

## 这一版解决什么

之前控制台只能看到一行 Agent 运行和折叠的步骤文本。出问题时，仍要翻库才能回答：是哪个子 Agent 失败、失败原因是什么、工具传了什么参数、返回了什么、哪一步最慢、花了多少 token。

这一版把同一条运行记录展开成可读的任务详情：

- 从任意子 Agent 点“详情”，都能看到它所在整棵父子树的根任务。
- 每个 Agent 显示状态、耗时、已用 / 预算 token、步骤数。
- 每一步显示工具或模型名称、状态、耗时、参数 JSON、结果摘要。
- 失败节点直接显示失败原因，不用再展开步骤找。
- 顶部汇总父子运行数、运行中 / 失败数、总墙钟、各 Agent 耗时合计、总 token、总步数。
- 超过 200 条运行或 20 层深度时明确标记“只展示前 200 条”，避免异常数据把控制台拖死。

## 接口

`GET /api/console/agent-runs/:id`

返回：

- `selectedId`：当前点进来的 run。
- `rootId`：所在树的根 run。
- `runs`：按父子顺序展开的运行数组，含 `depth`、`selected`、`agentId`、`status`、`budget`、`spentTokens`、`error`、`startedAt`、`endedAt`、`steps`。
- `steps`：`seq`、`kind`、`toolId`、`name`、`status`、`args`（已解析 JSON）、`resultSummary`、`durationMs`、`at`。
- `stats`：`totalRuns`、`activeRuns`、`failedRuns`、`totalSteps`、`totalTokens`、`wallMs`、`totalDurationMs`。
- `truncated`：是否因 200 条上限被截断。

鉴权沿用控制台接口：需要控制台会话或服务令牌，并且只能查当前公司的 run；跨公司返回 404。

## 前端入口

管理后台 → 系统 → Agent 运行列表 → 每行“详情”。

详情弹层支持刷新；父子节点用缩进和左侧连接线表达层级，当前选中的子 Agent 高亮。参数和结果用等宽小字号代码块，长内容在块内滚动，不把弹层撑爆。

## 边界

- 详情接口是只读查询，不改变运行状态；取消运行仍走原 `/cancel` 接口。
- 直连 SQLite 查询，按父子递归 CTE 取树；不跨公司、不跨库。
- 工具参数只在管理后台可见；普通员工端没有这个接口。
- 200 条 / 20 层是保护上限，不是业务限制。真遇到更大的树，下一步再做分页或按子树懒加载。
