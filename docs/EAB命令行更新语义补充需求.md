# EAB 命令行更新语义补充需求

> 日期：2026-11-21
> 适用：`scripts/eab.mjs update` 与 `scripts/eab-update.mjs`
> 关联：[EAB 一键更新需求与验收](./EAB一键更新需求与验收.md)

## 1. 背景

现有命令分两步：`eab update` 只检查版本，必须再执行 `eab update --apply` 才会真正安装；指定版本还要写成 `eab update --apply --version=<版本>`。命令冗长，而且“检查”和“安装”共用同一个入口，容易让用户误以为第一次执行已经完成升级。

本次把命令语义收敛为“执行即安装”：

- `eab update`：直接升级到 GitHub 最新版本。
- `eab update <版本>`：直接升级或降级到指定版本。
- 不再要求 `--apply`。

## 2. 权威口径

| 命令 | 行为 |
| --- | --- |
| `eab update` | 读取 GitHub 最新 Release；当前已是最新时不重装，退出码 0 |
| `eab update 2026.11.19` | 安装指定版本；高于当前为升级，低于当前为降级 |
| `eab update v2026.11.19` | 同上，允许带 `v` 前缀 |
| `eab update --version=2026.11.19` | 同上，兼容旧写法 |
| `eab update --version 2026.11.19` | 同上，兼容空格分隔写法 |
| `eab update --check` | 只检查最新版本并打印升降级关系，不停止服务、不安装 |
| `eab update 2026.11.19 --check` | 只检查指定版本，不安装 |
| `eab update 2026.11.21 --force` | 当前版本重装 |
| `eab update --apply` | 兼容旧写法，等同 `eab update`，直接安装 |
| `eab update --apply --version=...` | 兼容旧写法，直接安装指定版本 |
| `eab update --list` | 仍只列出 Release，不安装 |

## 3. 版本与参数规则

- 版本号格式为 `YYYY.MM.DD` 或 `YYYY.MM.DD.NN`，非法日期直接拒绝。
- 位置参数、`--version=<值>` 只能二选一；同时给出不同版本视为参数错误。
- 最多允许一个版本号；多个位置版本号直接拒绝。
- `--version` 不带值时报错，不退化成“升级最新版本”。
- 同版本默认不重装；只有显式 `--force` 才重新下载安装。
- 最新版本等于当前版本时输出“当前已是最新版本”，不调用更新器。
- 降级与升级走同一条安装链路，不额外增加确认步骤。

## 4. 执行与安全边界

- 除 `--check`、`--list`、同版本无 `--force` 外，命令都会真正安装。
- 安装前仍先停止服务，再调用 `scripts/eab-update.mjs` 完成下载、校验、备份、替换、依赖安装、重启和失败回滚；这些安全步骤不因去掉 `--apply` 而减少。
- `--check` 不停止服务、不写更新记录、不触发重启。
- 控制台“系统更新”仍只面向最新版本；命令行是唯一支持指定版本升降级的入口。
- 更新范围、备份口径、失败回滚和日志位置沿用《EAB 一键更新需求与验收》，本次不改变。

## 5. 输出要求

安装前至少打印：

- 当前版本。
- 目标版本，以及“升级 / 降级 / 重装 / 当前版本”的关系。
- Release 链接。
- 即将执行的动作，例如“正在停止服务并执行降级…”。

`--check` 额外打印“预览：将执行…，未安装”和去掉 `--check` 后的安装命令。

## 6. 验收用例

1. `eab update` 在最新版本高于当前版本时，直接调用更新器并传入最新版本号。
2. `eab update` 在当前已是最新版本时，不调用更新器，退出码 0。
3. `eab update 2026.01.01` 输出降级并直接安装，命令中不要求 `--apply`。
4. `eab update 2099.01.01` 输出升级并直接安装。
5. `eab update --version=2026.01.01` 与位置参数行为一致。
6. `eab update 2026.01.01 --check` 只预览，不调用更新器。
7. `eab update <当前版本>` 默认不重装，提示加 `--force`。
8. `eab update <当前版本> --force` 进入重装动作。
9. `eab update --apply` 仍可直接升级最新版本。
10. 非法版本、缺失 `--version` 值、多个版本号都返回非 0 并给出明确错误。
11. `eab update --list` 不触发安装。
12. 帮助文本与 README 不再把 `--apply` 写成必需步骤。

## 7. 本轮不做

- 不做交互式二次确认。
- 不改控制台更新入口的“仅最新版本”定位。
- 不新增离线包、本地目录或指定分支作为更新来源。
- 不改变更新器内部备份、校验和回滚协议。
