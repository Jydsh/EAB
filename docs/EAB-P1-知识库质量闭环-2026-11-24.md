# EAB P1 · AGT-15 知识库质量闭环

> 版本：`2026.11.23.04`（本轮未升级版本号）
> 日期：2026-11-24
> 审计来源：`docs/EAB-Agent框架对照审计与能力建设需求-2026-11-23.md` §7.2
> 验收口径：回答必须能展示所引知识库的**文档标题与片段**；表格题、图片题有**可重放基准**；资料带**更新时间与新鲜度风险提示**。

## 1. 本轮解决的问题

AGT-15 之前，检索能返回切片正文，但回答侧只看到一段文本：

- 用户不知道答案来自哪份文档，也无法判断片段是否被截断；
- 表格切片和图片切片混在正文里，没有类型、页码、工作表、行号；
- 旧制度与现行制度没有时间差提示，模型可能把 2024 年制度当 2026 年执行；
- 没有一套可以重复跑的表格题、图片题和过期资料题。

本轮把“检索质量”做成可观察结果：**引用面板展示标题、片段、类型、新鲜度；回答带更新时间说明；基准跑分可重放。**

## 2. 检索层元数据

`packages/server/src/kb-retrieval.ts` 的 `KbRetrievalHit` 新增：

| 字段 | 说明 |
| --- | --- |
| `layout` | `text` / `table` / `image` / `mixed`，附页码、工作表名、行号范围 |
| `freshness` | `fresh` / `aging` / `stale` / `unknown`，附中文标签、天数、更新时间、标题年份、提示语 |
| `docUpdatedAt` | 文档最后更新时间 |
| `docVersion` | 文档版本号，至少为 1 |

新鲜度阈值：

- 180 天内：`fresh / 较新`；
- 181–365 天：`aging / 较旧`；
- 超过 365 天：`stale / 可能过期`；
- 没有更新时间：`unknown / 更新时间未知`，默认要求核对。

标题包含明显旧年份时另加版本提示：`当前年份 - 标题年份 >= 2`，例如 2026 年检索到“2024年休假管理制度”，提示“标题标注 2024 年，早于当前版本，请核对”。

`diagnostics.freshness` 记录本轮命中里 fresh/aging/stale/unknown 的分布。

## 3. 召回精度修正

真实验收时发现两个会影响“回答带正确资料”的问题，已一并修正。

### 3.1 关键词召回补上文档标题

原关键词候选只匹配 `chunk.text` 和 `chunk.meta_json`，文档标题没有进入召回。用户问“年休假制度”时，文档标题里的“年休假制度”不参与命中，旧制度可能进不了候选。

现在候选 SQL 同时匹配 `d.title`，打分文本也加入文档标题。真实库验证：问“公司年休假制度，工作满20年有几天年假”，修复前过期制度不在前 6，修复后进入候选并排名第 1。

### 3.2 关键词精确命中保护

混合召回使用 RRF 融合关键词榜和向量榜。同一份文档往往有几十个切片同时进入向量榜，这些切片会靠“双路加分”挤掉关键词榜第 1 的精确命中。

真实验收中，过期制度在关键词榜第 1、分数 8，但混合榜前 6 全是《快奖快罚管理制度》。原因是向量榜里《快奖》的多个切片都拿到了双路分数。

现在在融合排序后保留**首条关键词分 ≥2 的命中**，再按融合顺序补足其余位置。问“年休假制度，工作满20年有几天年假”时，过期制度稳定排第 1，回答可以直接引用。

### 3.3 标题同名切片优先

问“变电站设备巡检图示”这类与文档标题完全同名的问题时，正文切片和图片切片会拿到相同关键词分。现在正文里完整出现文档标题的切片额外加 1 分，标题页或主图优先命中，图片题不再落到纯文字切片。

## 4. 回答侧引用与新鲜度

`packages/server/src/routes/chat.ts`：

- `ChunkHit` 接收 `layout / freshness / docUpdatedAt / docVersion`；
- `knowledgeContextBlock()` 给每个 `[K]` 加“资料状态：正文/表格/图片｜更新时间说明”；
- 存在需核对资料时，系统提示注入“【新鲜度提示】”，要求回答写明资料更新时间并提示核对最新版本；
- 新增 `KbCitationMeta`、`citationFromChunkHit()`、`answerCitations()`、`kbCitationsFromToolResult()`；
- 自动检索与 `kb.search` 工具命中的引用合并去重，最多 8 条；
- `AgentToolTrace` 新增 `kbCitations`，`kb.search` 执行完成时从工具 payload 提取引用；
- 最终消息 `meta.citations` 带标题、180 字片段、layout、freshness、docVersion、首张图片。

`packages/server/src/routes/tools.ts` 的 `kb.search` 返回补充 `docId / chunkId / layout / freshness / images`，使工具检索路径也能进入引用面板。

## 5. 员工端资料面板

`packages/server/public/chat.js` 新增 `knowledgeSourceHtml()` 和 `.kb-source-slot`：

- 回答下方显示“资料 · 参考 N 条知识库资料”，有风险时显示“N 条需核对”；
- 展开后每条显示：
  - `[K1] 文档标题`
  - 集合名
  - 正文 / 表格 / 图片类型
  - 页码 / 工作表 / 行号
  - 新鲜度徽标
  - 180 字片段
  - 可选图片缩略图
- 实时回答和刷新后的历史回答都渲染；
- `bindToolToggles` 支持 `.kb-source-head / .kb-source-panel`。

`packages/server/public/chat.css` 增加对应样式，徽标颜色：

- 较新：绿；
- 较旧：黄；
- 可能过期：红；
- 未知：灰。

## 8. 已知边界

- 路由器对“核心交换机管理地址”这类短问句不一定自动触发知识库检索；模型首轮也可能不主动调 `kb.search`。用户明确要求检索，或问题命中制度类关键词时，路径正常。这是现有路由行为，不属于本轮新增缺陷。
- 新鲜度只依据文档更新时间与标题年份，不知道制度是否已被新版本替代；提示语是“请核对”，不自动判定作废。
- 引用面板最多展示 8 条，超出部分仍参与回答上下文但不展示。
- 表格数值校验目前依赖基准集与片段文本，不解析单元格坐标。
