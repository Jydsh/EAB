## 一、目标

控制台「模型接入 → 用途路由」里的 8 个用途，从"配置位"变成"真功能"：

- **配置了**：对应功能真的调用这个模型。
- **没配置 / 调用失败 / 上游不可用**：一律降级，保持现有对话、检索、渠道消息完全不变，不向用户抛错。
- **不做静默换模型**：降级只表现为"该能力这一步被跳过"，不改变用户已选择的对话模型。

## 三、统一设计约定

1. **只有"显式绑定"才启用重量级能力**（意图判定、语音、视频）。
   判定依据 `explainModelRoute(db, companyId, purpose).source === 'route'`。
   原因：`resolveModelForPurpose` 在未绑定时会按能力自动回退，`router.intent` 的回退条件几乎覆盖所有 chat 模型——若不区别对待，每轮对话都会多调一次模型。
2. **路由能力失败只降级**：`try/catch` + `console.warn('[route] xxx 降级：...')`，不阻断主流程。
3. **用户主动操作才允许报错**：如点「朗读」而 TTS 未配置，返回 `400` + `hint`，由前端提示。
4. **降级可观测**：对话事件 / 接口响应里带 `degraded: true` 与原因，便于排查。
5. **体积与超时**：新增调用一律带 `AbortSignal.timeout`；音频、视频入参限制大小。
6. **不改默认行为**：未配置任何路由时，行为与改动前逐字节一致。

## 四、分步实施

### Step 1 · `chat.vision` 按路由取模型（约 0.5h）

- 文件：`packages/server/src/routes/chat.ts`（选型段 2615-2637）、`dingtalk-bot.ts:897`、`feishu-bot.ts` 同类选型
- 改动：
  - 带图消息时先 `resolveModelForPurpose(companyId, 'chat.vision')`
  - 该模型须同时满足：在 `available`（角色可见）内、`modelSupportsVision` 为真；否则回落 `imageModels[0]`
  - 用户显式指定的模型不支持图片时的拦截逻辑保持不变
- 降级：未绑定 → 仍按能力自动挑（现状）
- 验收：绑 A 不绑 B → 带图进 A；A 停用/无权限 → 回落 B，不报错

### Step 2 · `router.intent` 意图判定（约 2h）

- 新文件：`packages/server/src/intent.ts`
  - `classifyChatIntent(db, dbPath, companyId, text, options?) → { intent: 'org' | 'kb' | 'chat', confidence, modelId } | null`
  - 仅 `source === 'route'` 时执行；`callModel` + 强约束 JSON（`{intent,confidence}`），解析容错（截首个 `{...}`，失败再用关键词兜底，再失败返回 null）
  - 8s 超时；失败只 warn
- 接入：`routes/chat.ts` 消息管线（检索前），把结果写入 run 事件；`intent === 'org'` 时向 system 提示追加"优先 org.directory"；`intent === 'kb'` 时强制走知识库检索；`chat` 无附加提示
- 降级：未绑定 → 不判定，管线与现状一致
- 验收：绑定时事件里可见 `intent`；解绑后无额外模型调用；判定失败不影响回答

### Step 3 · `asr.default` 语音转写（约 3h）

- `llm.ts` 新增：
  - `callTranscription(db, dbPath, companyId, modelId, audio: { buffer, mime, fileName }) → { text }`
  - OpenAI 兼容 `POST /audio/transcriptions`（multipart）；Azure 走 `/openai/deployments/<model>/audio/transcriptions`；Gemini 用 `inline_data`；Anthropic 明确 400
- 新路由：`POST /api/chat/transcribe`（`{ dataUrl }`，音频白名单 + ≤20MB），未配置 → `400` + hint
- 前端：输入区加「语音」按钮（`MediaRecorder` 录音 → 转写 → 填回输入框）；无 asr 绑定 → 按钮 disabled + title 说明
- 渠道：钉钉 `msgtype=audio/voice` 的 `downloadCode` → 下载 → 转写 → 走文本链路；下载或转写失败提示"收到语音，但未配置语音转写"
- 验收：配 whisper 类模型后录音可出文字；未配置时按钮禁用、原聊天与文件流程不变

### Step 4 · `tts.default` 语音合成（约 2h）

- `llm.ts` 新增 `callSpeech(db, dbPath, companyId, modelId, text, opts) → { buffer, mime }`（OpenAI 兼容 `POST /audio/speech`，Gemini/Anthropic 不支持 → 400）
- 新路由：`POST /api/chat/speech`（`{ text }` 上限 600 字）→ `audio/mpeg`
- `/api/chat/models` 增加 `speech: { available: boolean }`，前端据此显示「朗读」按钮
- 降级：未绑定时按钮不出现
- 验收：配 TTS 后点朗读可播；未配置无按钮、无接口调用

### Step 5 · `video.analyze` 视频理解（约 4h+，依赖 ffmpeg）

- 依赖：`ffmpeg`（本机当前未安装 → 缺失即降级，明确提示"视频理解需要 ffmpeg"）
- 流程：视频 → 抽音频 → `asr` 转写（无 asr 跳过）→ 抽 4~8 帧 → `chat.vision`/`video` 端点逐帧描述 → 汇总成本轮上下文片段
- 新路由：`POST /api/chat/video`（≤50MB）；未配置任一环节 → 返回缺失清单
- 验收：三件齐全时给出视频摘要；缺任一环节 → 明确说明缺哪一环，不报未知错误

## 五、降级矩阵

| 场景 | 行为 | 用户可见表现 |
| --- | --- | --- |
| 用途未绑定，且无可用候选 | 跳过该能力 | 无变化 |
| 用途未绑定，但存在自动候选 | 仅 `chat.vision` / `kb.rerank` 走自动挑；`router.intent` / `asr` / `tts` / `video` 不启用 | 无变化 |
| 绑定的模型被停用 / 无权限 | 视同未绑定 | 无变化（日志留痕） |
| 调用超时 / 上游 5xx | 单次降级，不影响本轮回答 | 无变化（日志留痕） |
| 用户主动使用（朗读 / 录音 / 视频） | 返回 400 + hint | 弹提示：需要先绑定哪类模型 |
