# EAB P1 · 容器化与多实例 v1（AGT-17）

日期：2026-11-24
版本：2026.11.23.04（本轮不改版本号）
范围：Dockerfile / Compose / 运行角色 / 健康探针 / 队列持久化验证 / 水平扩容边界

## 1. 这轮解决了什么

审计 AGT-17 的四条验收，本轮对应如下：

| 验收 | 交付 | 状态 |
| --- | --- | --- |
| 一条命令起服务 | `Dockerfile` + `docker-compose.yml` + `deploy/nginx.conf`；配好 `.env` 后 `docker compose up -d --build` | 文件已交付；本机无 Docker，未实际构建 |
| 健康探针 | 复用 `/readyz`（真实 `SELECT 1`）与 `/api/health`；镜像内置 30 秒 healthcheck | 本机三进程实测 `/readyz` 200 |
| 任务不因重启丢 | `async_jobs` 为权威状态；90 秒租约 + 心跳 + 过期回收；worker 重启后继续领取 | 本机真实停 worker、入队、重启消费通过 |
| 可水平扩 | `api` 角色只接 HTTP、不跑单例后台；Compose 网关按 DNS 轮询 `api`；`--scale api=N` | 本机同库 2 个 api 同时健康；容器扩缩未实跑 |

同时补上了审计原文没有写、但不是它就跑不起来的两个前提：

1. **多实例启动闸门**：原来的 `acquireProcessLock` 明确禁止同一数据目录第二个进程，本轮只有显式 `EAB_MULTI_INSTANCE=1` 才跳过独占锁。
2. **跨进程选主**：没接 Redis 时，新增 `runtime_coordination` 表作为 TTL 租约层，让定时任务、组织同步、任务图等待恢复这些“只能一个实例干”的循环不会每个副本各跑一遍。

## 2. 部署拓扑

```
浏览器
  │  8787 员工 / 8788 控制台
  ▼
nginx（唯一对外入口，SSE 关闭缓冲）
  │
  ├── api×N     只做 HTTP/SSE；不消费队列、不建渠道长连接、不跑定时任务
  └── worker×1  队列消费者 + 所有单例后台循环；仍监听 8787/8788 供健康检查
        │
        └── redis（跨实例唤醒、频控；故障时降级）
        │
        └── eab-data 卷：SQLite 主库 + 云空间 + 插件目录
```

### 角色边界

| 能力 | api | worker | all（默认，单机） |
| --- | --- | --- | --- |
| 员工端 / 控制台 HTTP | 是 | 是（仅供探针与内部调用） | 是 |
| 异步作业消费 | 否 | 是 | 是 |
| 用户定时任务 | 否 | 是 | 是 |
| 组织同步 | 否 | 是 | 是 |
| 钉钉 / 飞书 Stream 长连接 | 否 | 是 | 是 |
| 任务图等待恢复 | 否 | 是 | 是 |
| 启动期全局 Agent/团队任务清理 | 否 | 否（多实例跳过） | 是 |
| 保留清理 | 否 | 是 | 是 |

单例循环内部仍保留 `runAsLeader`：Redis 在线时走 Redis 租约，Redis 不可用且 `EAB_MULTI_INSTANCE=1` 时走 `runtime_coordination` 数据库租约。api 角色直接不起这些定时器，避免空转。

## 3. 一条命令起服务

前置：

1. 安装 Docker Engine / Docker Desktop（含 Compose v2）。
2. 在仓库根执行：

```powershell
Copy-Item .env.example .env
# 编辑 .env，至少把 EAB_CONSOLE_TOKEN 换成随机长串
```

启动：

```powershell
docker compose up -d --build
```

或者：

```powershell
pnpm docker:up
```

访问：

- 员工工作台：`http://<host>:8787/chat`
- 管理控制台：`http://<host>:8788/admin`
- 就绪探针：`http://<host>:8787/readyz`

停止：

```powershell
docker compose down
```

数据卷 `eab-data` 不随 `down` 删除；要彻底清空需显式 `docker compose down -v`。

### 扩容

```powershell
docker compose up -d --scale api=2 --no-recreate
```

nginx 用 Docker DNS `api:8787` 每请求重新解析，不需要重启网关。worker 建议保持 1 个：它承担渠道长连接与单例后台循环，队列本身虽然支持多消费者，但同一套 Stream 凭证多开会增加重复连接和平台限流风险。

## 4. 队列语义（现有实现 + 本轮收紧）

`async_jobs` 是权威状态，进程内队列只做唤醒，不存任务本体。

- 提交：`submitJob` 落库为 `queued`，再通过本实例唤醒 + Redis Pub/Sub 唤醒。
- 抢占：`claimJob` 先取候选 id，再 `UPDATE ... WHERE status='queued'`；只有 `changes=1` 的实例拿到。
- 租约：本轮 worker 租约从默认 5 分钟收紧到 **90 秒**，心跳每 30 秒续租。
- 重启：`recoverStaleJobs` 把租约过期的 `running` 放回 `queued`；worker 启动时执行一次，之后由领取逻辑继续。
- 结果：`completeJob` / `failJob` 都带 `lease_owner` 条件，旧实例不能覆盖新实例的结果。
- 未知 kind 不会被领取：worker 只 `claim` 已注册 handler 的 kind，避免把别的模块的作业误判失败。

因此“重启不丢”成立；代价是进程被 `kill -9` 后，最长约 90 秒才会被另一个 worker 接走。正常容器 `stop` 会走退出流程，但当前实现仍不等待在跑作业结束，文档按 90 秒上限描述。

## 5. 健康与就绪

`/readyz`：执行 `SELECT 1`，返回 `role` 与 `instanceId`。数据库不可用即失败，适合容器 healthcheck 和负载均衡摘流。

`/api/health`：在原有版本/PID/端口信息上新增：

- `instanceId`：`EAB_INSTANCE_ID` 或 `host:pid`
- `role`：`all | api | worker`
- `multiInstance`：是否显式多实例

镜像 healthcheck：

```text
node -e "fetch('http://127.0.0.1:8787/readyz').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"
```

## 6. 配置项

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `EAB_SERVER_ROLE` | `all` | `all` 单机全量；`api` 只接 HTTP；`worker` 跑单例后台 |
| `EAB_MULTI_INSTANCE` | `0` | `1` 才跳过单写进程锁并启用数据库租约；必须同时指定 api 或 worker |
| `EAB_INSTANCE_ID` | 自动 | 多实例展示与排障用；不填则 `host:pid` |
| `EAB_BACKENDS_FROM_ENV` | `0` | Compose 置 1，允许用环境变量接 Redis |
| `EAB_REDIS_URL` | 空 | Compose 指向 `redis://redis:6379` |
| `EAB_CONSOLE_TOKEN` | 空 | Compose 必填；启动前在 `.env` 配好 |

`EAB_MULTI_INSTANCE=1` 与 `EAB_SERVER_ROLE=all` 的组合会在启动时直接报错，避免“看起来多实例、实际每个副本都跑单例后台”。

## 8. 边界与风险

1. **只支持同机多容器共享 SQLite**。所有副本必须挂同一个 `eab-data` 卷；SQLite 依赖本机文件锁，跨主机共享网络盘会破坏一致性。
2. **跨主机水平扩未完成**。真正多主机需要先把主存储切 PostgreSQL；当前 `packages/storage/src/db.ts` 只有 SQLite 主存储，本轮没有造这个能力。
3. **worker 建议单副本**。多 worker 的队列消费是安全的，但渠道长连接、启动期全局清理、插件目录同步等仍按“一个 worker”设计。
4. **多实例下跳过全局 Agent/团队任务清理**。代价是异常退出留下的 `running` 记录不会被启动扫描收尾；需要用单实例维护窗口处理，或后续做实例心跳表后按实例回收。
5. **Redis 故障切换存在短暂双主窗口**。Redis 掉线时切到数据库租约，Redis 恢复后又优先用 Redis；旧数据库租约到期前可能短暂两边都认为自己可领导。TTL 内窗口有限，但渠道长连接已有 `isHeld()` 巡检兜底。
6. **镜像用 tsx 直接跑 TypeScript**。仓库目前没有稳定 `dist` 构建产物，镜像保留全量依赖，体积偏大；这不是“最优生产镜像”，但保证容器与本机同一启动路径。

## 9. 回滚

- 不启用多实例：去掉 `EAB_MULTI_INSTANCE` / `EAB_SERVER_ROLE`，恢复单进程 `all`，进程锁重新生效。
- 容器回滚：`docker compose down` 后用上一镜像 tag 起；数据卷不动。
- 数据库回滚：`0098_runtime_coordination.sql` 只新增一张 TTL 键值表，不参与业务账本；保留表不影响单实例运行。需要彻底回退时停服后删表。
