# EAB P1 · AGT-13 记忆 OS（四类记忆、冲突待确认、混合召回）

> 版本：`2026.11.23.04`（本轮未升级版本号）
> 日期：2026-11-24
> 审计来源：`docs/EAB-Agent框架对照审计与能力建设需求-2026-11-23.md` §6.5
> 验收口径：记忆分四类；用户偏好/个人事实必须确认；冲突不静默覆盖；召回从词面升级为“词面 + 向量”；情景记忆按时间衰减，偏好/决策不衰减。

## 1. 本轮解决的问题

AGT-13 之前，长期记忆只有一段 `content` 和一个 `confirmed` 标记：分不出“偏好”和“决策”，也没有冲突概念；召回只按词面交集，旧任务经验和新决策同权；两台设备上的向量能力完全没有用到记忆上。

本轮把记忆拆成 **preference / fact / decision / episode** 四类，并把“写入判定、确认替换、召回排序”做成一条闭环。

## 2. 数据模型

新增迁移 `packages/storage/migrations/0096_memory_os.sql`：

| 字段 | 作用 |
| --- | --- |
| `memory_type` | 四类之一，默认 `fact` |
| `conflict_with` | 指向同公司、同范围、同类型的一条旧记忆 |
| `embedding` | float32 向量 BLOB，没有向量模型时保持 NULL |
| `embedding_model` | 生成该向量的模型 id，模型换了会重算 |

历史记忆统一回填成 `fact`，不把未知内容误当偏好或决策。

新增索引 `idx_memories_type (company_id, scope_type, scope_id, memory_type, deleted_at)`，避免按类型查重时全表扫。

## 3. 写入与冲突规则

### 3.1 四类记忆

| 类型 | 中文 | 典型内容 | 衰减 |
| --- | --- | --- | --- |
| `preference` | 偏好 | 汇报要一页纸、回答先给结论 | 不衰减 |
| `fact` | 事实 | 项目代号、负责人、环境地址 | 不衰减 |
| `decision` | 决策 / 口径 | 周报周五 17:00 前提交、统一用某模板 | 不衰减 |
| `episode` | 情景经验 | 某次任务踩过的坑、有效步骤 | 45 天半衰期 |

### 3.2 必须确认

- `POST /api/memories` 新增记忆一律 `confirmed=0`；缺省类型是 `preference`。
- `memory.propose` 的团队规则缺省类型是 `decision`，落公司级待确认，仍需管理员确认。
- `user` 层记忆本人确认即可；`dept` / `company` 层必须 `memory:admin` 确认或删除。
- 未确认记忆不进入对话上下文。

### 3.3 重复与冲突

写入前调用 `findMemoryDuplicateOrConflict()`，只在**同公司、同范围、同类型**内比较：

- 归一化后完全相同：返回已有 id，`duplicate: true`，**不插新行**；
- 与已确认旧记忆相似度 ≥ `0.5`：新记忆仍落 `confirmed=0`，同时写 `conflict_with=旧记忆 id`，状态为 `conflict`；
- 两条待确认记忆允许并存，交给用户逐条处理；
- 两条已确认记忆之间不做批量互删。

确认冲突记忆时，在一个 `withTransaction()` 事务里：先软删除旧记忆，再把新记忆置为 `confirmed=1, conflict_with=NULL`。审计同时记录 `memory.confirm` 和 `replacedConflictId`。

**边界**：相似度是字符二元组 Jaccard + 短句包含加成，属于启发式拦截，不是模型语义判定；最终是否替换仍由用户确认。这样做避免引入额外模型调用，也不会自动覆盖。

## 4. 混合召回

`selectRelevantLongTermMemories()` 保留原来的调用形式，新增 options：

- `limit`：默认 3；
- `queryVector`：当前问题的向量；
- `vectorThreshold`：默认 0.55；
- `now`：便于测试固定时间。

召回通道：

1. **词面**：至少一个长度 ≥3 的实体，或命中两个以上检索词；
2. **向量**：词面未命中，但余弦相似度 ≥ 0.55 也可进入；
3. **混合分**：`keywordScore * 1.1 + vectorScore * 0.9`；
4. **情景衰减**：`episode` 额外乘 `0.45 + 0.55 * exp(-ageDays / 45)`，很久以前的经验仍保留约 45% 权重，不直接删除；偏好、事实、决策权重恒为 1；
5. 排序后截断 limit，同分保持原数组顺序。

### 4.1 向量生成与降级

`loadMemoryEmbeddings()`：

- 用 `resolveModelForPurpose(db, companyId, 'kb.embed')` 找向量模型；
- 一次批量送“当前问题 + 缺向量的候选记忆”给 `callEmbeddings`；
- 同模型已有向量直接复用，不重复调用；新向量落库；
- 没有模型、调用失败、返回条数不符时返回 `null`，对话链路自动退回纯词面召回，不阻断回答。

`embedMemoryRow()` 在写入和确认时做 best-effort 单条向量预生成，失败不影响记忆落库。

### 4.2 对话接入

`routes/chat.ts` 每轮取最近 20 条候选记忆，带 `id / content / memory_type / created_at`；有候选时尝试批量向量，再交给混合召回。

系统提示从 `- 内容` 改为 `- [偏好/事实/决策/情景] 内容`，模型能区分“用户偏好”和“已确认口径”。

消息 meta 新增 `longTermMemoryRecall`，每条带 `memoryType` 和 80 字 `excerpt`；`contextLayers.longTermMemories` 仍保留数量。

## 5. 记忆管理界面

`public/chat.js` 的“我的记忆”弹层：

- 每条显示 `已确认 / 待确认 / 冲突待确认`，并显示类型；
- 冲突记录显示“与旧记忆冲突：旧内容前 60 字”，按钮变为“确认替换”；
- 新增类型下拉，默认偏好；保存时传 `memoryType`；
- 说明改为“偏好/事实先进待确认区；冲突不自动覆盖，确认替换后旧记忆才失效”。

真实浏览器验收时发现一个布局缺陷：列表变长后，底部悬浮操作栏会遮住新增输入框。已给弹层加 `memory-modal` 类，把底部操作改为静态排布，并限制列表高度、允许滚动。

## 7. 当前边界

1. 冲突判定是字符相似度启发式（阈值 0.5），不是语义模型判定；不同表述但同义的冲突可能漏拦，最终仍靠用户确认。
2. 向量召回依赖 `kb.embed` 模型；没有模型或调用失败时只做词面召回，这是有意降级。
3. 本轮没有对历史记忆批量补向量；第一次召回时会按需补算并落库。
4. 历史记忆统一归为 `fact`，不自动猜测成偏好或决策。
5. 版本号仍为 `2026.11.23.04`；是否升级、是否 commit/push 按用户要求另行确认。
